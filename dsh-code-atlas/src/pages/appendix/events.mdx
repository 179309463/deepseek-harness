    <h2>Cordis 事件（活调用，不落盘）</h2>

    <p>这些是第 1 章五种派发模式的实际用例；它们不进日志，但 waterfall/serial 链上的决策结果会以 Session 事件的形式留下痕迹。</p>

    | 事件名 | 模式 | 一句话语义 | 挂载/触发位置 |
    |---|---|---|---|
    | `tools/pre-execute` | waterfall | 工具执行前闸门；不调 next 即 veto | core/tools/src/index.ts:1475 |
    | `tools/execute` | waterfall | 包住工具体的执行链（超时策略在此） | core/tools/src/index.ts:1573 |
    | `agent/pre-step` | waterfall | 步前决策：compaction、上下文注入可改写输入 | core/agent-loop/src/agent.ts:234 |
    | `agent/turn-stopping` | serial | 轮收尾：监听器用 steer 改写数据而非否决 | core/agent-loop/src/agent.ts:296 |
    | `llm/stream` | waterfall | 模型调用链；model-visible ⟺ logged 的 invariant 挂在这里 | llm/llm/src/index.ts:924 |
    | `session/event` | emit | Session 事件提交后的广播：持久化、投影、遥测订阅它 | core/session/src/index.ts:643 |
    | `internal/config` | waterfall | 插件 config 插值（`!!js` 求值） | vendor/loader/src/index.ts:92 |

    <h2>两条约定</h2>

    <p><strong>Declaration merging 扩展约定：</strong>新事件必须合并到 <code>@deepseek-ai/dsh-session/types</code> 的 <code>SessionEventMap</code>（不是根包）。合入后事件默认是 required-on-read：不认识该类型的构建会拒绝加载日志，除非事件信封携带 <code>ignorable: true</code>。</p>

    <p><strong>SESSION_FORMAT_VERSION = 0 的语义：</strong>预发布阶段日志格式不做任何兼容承诺——后端按版本号拒载异版日志，不提供迁移。加普通事件类型不 bump（由 <code>ignorable</code> 兜底）；只有 header、信封、核心事件语义或 surface 机制这类结构性变更才 bump。</p>
