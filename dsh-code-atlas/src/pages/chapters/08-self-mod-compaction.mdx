`apply` 一进场就做了三件事，顺序本身就是教学：

1. **先交规程**：`CORDIS_SYSTEM_PROMPT` 以 `order: 115` 插进系统提示词——模型在拿到工具之前，先拿到「使用说明书」。
2. **再装镜子**：每个 Inspect Provider 通过 `ctx.effect` 注册进 `ctx.cordisInspect` 注册表——还记得第 1 章吗，注册即副作用，卸载即逆序撤销。
3. **最后发工具**：`cordis_inspect_list` 只读列出 Host 与 Client 两侧全部 Provider；同文件往下还有 `cordis_inspect_query`（精确查签名）、`cordis_inspect_self`（查本会话的动态插件），然后才是 `cordis_define` / `cordis_run` / `cordis_stop` / `cordis_undefine`（41-379 行）。

为什么照镜子排在改装前面？看 381-398 行的 `agent/pre-step` 监听器就知道：用户输入 `@pluginId` 时，插件会把该插件的身份、版本指针、运行状态作为上下文消息注入，但**故意不含源码**——模型必须先 `cordis_inspect_self` 读回精确源码才能动手改。先照镜子，再动刀子。

</div>

这 107 行提示词是自改装真正的「安全带」。逐条拆它的设计意图：

- **划定边界**：定义只活在当前进程内存里，不写盘、不改仓库——所以 dsh 重启后动态插件天然清零，不存在「改装残留」。
- **诚实的威胁模型**：沙箱「防误用，不防恶意代码」——这句话写在规程里，提醒模型（和读者）别把 vm 沙箱当安全边界，真正的闸门是用户审批。
- **状态机纪律**：`cordis_run` 返回 `awaiting-approval` 时不许假装成功、不许轮询、被拒后不许重复请求；失败后**修同一个 Plugin**，不许偷偷新开一个顶替。
- 规程后半（56-107 行）还预演了高频翻车：可选服务用 `ctx.get`、硬依赖才写 `inject`、只写纯 JS（没有 TypeScript/JSX 转换）、别把活对象 `JSON.stringify`、**每个副作用必须可逆**。

写模型可见文本的第一原则在这里体现得淋漓尽致：全程站在模型视角说话，不出现 UI、传输层、实现的词汇。

</CodeWalk>

工具层与服务层的分工先厘清：`cordis_define` 走到服务的 `define`（151-202 行），只做参数校验、语法预检（`precheckCode`）和入库——**一行代码都不执行**。真正通电是 `cordis_run` 之后的 `startHost`：

1. `createSandbox` + `evaluateHostCode` 在 vm 沙箱里求值模型写的纯 JS 函数体，同步超时由 Config 的 `vmTimeoutMs`（默认 5000ms，127-129 行）卡住。
2. 返回值必须过 `isPlugin` 校验——这就是第 1 章 `RegistryService.plugin` 认识的三种形态之一：函数或带 `apply` 的对象。

4. catch 里先把已注册的 Host handler 全部 dispose 再上报——**失败路径也不留副作用**。

Client 半边不在 Node 进程里跑：浏览器通过 Typert `@Remote` 方法（`runHostHalf`、`getClientCode`、`invoke` 等）与 Host 对暗号，含 Client 代码的 Package 还要先过用户审批（`run` 的 270-311 行：未授权就停在 `awaiting-approval`）。Host 管文件/网络/Agent，Client 管主题/Slot UI，两边只许无损 JSON 来往——这就是 host runner 与 client runner 的分工。

compaction 挂在第 5 章讲过的 `agent/pre-step` waterfall 上：**每次模型调用之前**，先用 `ctx.tokenMeter` 给当前 surface 称体重，超过路由模型的 `thresholdRatio` 阈值就触发 `pressure` 压缩。

注意两个防御细节：

- 压缩失败只 `warn` 然后 `return next()`——**瘦身是优化，不是闸门**；配置错了（`TargetPressureConfigError`）每个目标只警告一次，避免刷屏。
- 它是 waterfall 监听器，规约铁律：结束时必须 `next()` 把决策权交回主流程。

第二触发口在 179-223 行的 `agent/request-error`：provider 确认 `CONTEXT_WINDOW_EXCEEDED` 时走 `context-overflow` 恢复——绕过正常阈值强制压一轮，然后返回 `{ kind: 'retry' }` 让 loop 重试；重试次数有 `maxOverflowRetries` 上限，一次成功响应就清零（167-177 行）。两条路径都先尝试 `pruneSession`（可选的 `toolResultPruner` 服务，把超长工具结果截头去尾），再选区做 LLM 摘要，最后保留最近 `retainTokens` 预算的尾部原文。

整个压缩是一次**记录在日志里的事务**，durable 锁就是 `compaction/start` 这个事件本身：

1. **上锁**：`session.append('compaction/start', …)`。因为它是 durable 的，进程崩溃重启后日志里仍留着一个「未配对」的 start，`assertCompactionInactive`（286-298 行）会拒绝并发压缩——内存锁做不到的，日志锁做到了。
2. **摘要**：`summarizeCompaction` 调 LLM 把选区浓缩成结构化 checkpoint。妙处在 summarizer.ts：摘要请求**原样重放本会话的 system prompt、工具列表和消息前缀**，只在尾巴追加一条压缩指令——对 provider 来说这是一次真前缀调用，**KV cache 直接复用**，省钱省延迟。
3. **复查**：摘要返回后 `assertStable` 重测 surface——异步期间有人改了历史就抛 `SurfaceChangedError`，绝不拿旧摘要盖新历史。
4. **落盘**：`commitCompactionBody`（427-478 行）追加 `compaction/summary` 事件，再追加一条来源为 compact checkpoint 的 `user/message`，带 `surfaceOp: { op: 'replace', start, end }`——第 4 章的 surface 投影在这里完成「一段历史换一个节点」的替换。
5. **解锁**：任何结局都恰好尝试一次 `compaction/end`——成功路径在紧随其后的 214-217 行，失败也在 218-229 行的 catch 里补写带 `error` 的 end，尝试记录永久留在日志里。

手动 `/compact` 走的是同一台机器：`command-compact` 调 `compactNow`，经 `agent.runMaintenance` 确认 agent 空闲后以 `owner: null` 开一个独立事务，还多要一个 `sessions.flush` 耐久检查点——人下的命令，值得一次落盘保证。

## 胖虎翻车现场

> 胖虎：「我让 agent 给我写个动态插件，它 `cordis_define` 三次全报错！什么破工具！」

胖虎让模型写的「插件」里带着 TypeScript 泛型和 `import`——而 define 的预检（`precheckCode`）只接受**纯 JavaScript 函数体**，不做任何 TS/JSX/打包转换，`code.host` 里有类型标注直接拒收。规程第 75-80 行早就写了这条，胖虎没读。

好不容易改成纯 JS 跑起来了，胖虎又让插件「每 5 秒打印一次心跳」，写的是裸 `setInterval`。`cordis_stop` 之后，控制台还在咚咚咚——定时器没走 `ctx.effect`，Fiber dispose 时没人替它收尸。规程第 88-92 行同样写了：**每个副作用必须可逆**，要么 `ctx.effect`，要么官方返回 disposer 的 API。两条铁律都在提示词里，翻车只因为没读说明书。

## 小结卡

- 自改装三件套：`inspect`（照镜子）→ `define`（只登记不动电）→ `run`（沙箱求值 + 挂 Fiber 通电）；`stop` 保留版本、`undefine` 永久删除。
- 热插拔不是新机制：动态插件就是普通 Cordis 插件，effect/dispose 逆序清理兜底一切副作用。
- `CORDIS_SYSTEM_PROMPT` 是模型视角的安全规程：进程内存边界、审批纪律、失败修同一个 Plugin、副作用必须可逆。
- compaction 双触发：`agent/pre-step` 压力检查 + `agent/request-error` overflow 恢复；策略是 prune 旧工具结果 → LLM 摘要中间历史 → 保留 `retainTokens` 尾部。
- 事务三件套：durable `compaction/start` 锁、摘要后稳定性复查、`surfaceOp: replace` 落盘；`/compact` 手动命令多要一次 flush。
