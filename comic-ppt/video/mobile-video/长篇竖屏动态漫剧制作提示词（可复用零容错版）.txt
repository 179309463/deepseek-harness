# 长篇竖屏动态漫剧制作提示词（可复用零容错版）

> **使用方式：** 上传新的分镜脚本文档后，将下方“可直接粘贴的提示词”完整发送。若有指定画风、配音风格、交付格式或片尾信息，可在提示词末尾的“可选制作偏好”中补充；没有补充时，严格以附件脚本为唯一内容依据。

## 可直接粘贴的提示词

```markdown
请严格依据我刚上传的**完整分镜脚本文档**，制作一支完整的 **9:16 竖屏动态漫剧视频**。这是长视频制作任务，**绝不是 4 秒或单镜头演示视频**。附件是剧情、镜头、时长、台词、屏幕文字、角色、技术信息和结尾钩子的唯一内容依据；未经我明确要求，不得删减、改写、扩写、错序或擅自补充剧情与技术事实。

# 一、不可违反的总原则

1. **逐镜头原始时长绝对优先。**
   - 必须逐条读取并建立“镜头制作清单”，对每一镜锁定：镜头编号、原始时长、画面动作、角色、原始台词、屏幕/技术文字、环境声、转场方式。
   - 每一镜必须按附件写明的原始时长制作，例如 6 秒、8 秒、9 秒、10 秒、11 秒、12 秒、13 秒等。不得因为生成模型的默认时长、单次时长限制或所谓节奏优化，而把镜头压缩成 4 秒或其他短片段。
   - 先计算全部镜头时长之和，并在最终交付前核验总时长。最终视频总时长必须与脚本总时长一致，允许的编码误差不超过 0.5 秒。

2. **不使用视频生成时自动附带的中文配音。**
   - 所有视频画面均须以**静音画面**生成，即关闭或不请求视频内置语音、对白、旁白和自动配乐。
   - 中文对白、中文旁白、技术名词读音、停顿和人物情绪，必须在所有视频画面完成后，使用独立的高质量普通话音频生成流程制作，再进入后期混音。
   - 禁止把“视频内置中文配音”作为任何镜头的最终音轨，以避免发音错误、台词错漏、技术词误读和不可控音质。

3. **所有文字以脚本文档为准。**
   - 人物台词、旁白、终端命令、产品名称、英文缩写、技术术语、标题、章节卡、风险提示与片尾文字都必须从附件逐字提取和校对。
   - 屏幕上的关键信息与字幕要通过后期文字/字幕轨精确叠加，不依赖画面模型在视频帧内自动生成小字或代码。
   - 对英文技术词、包名、命令、缩写和代码必须保留附件原写法；配音提示中应明确这些词的读法，字幕中不得擅自翻译或修改。

4. **先完成全部画面，再开始音频。**
   - 先完成并核验全部静音视频镜头，确认没有漏镜、错序、错时长或错画幅。
   - 只有在“全部静音画面已完成”的里程碑明确报告后，才开始生成独立中文配音、音乐、音效和字幕。
   - 不要在前几个视频镜头未完成时停在音频生成阶段，也不要让用户看到长时间无结果的音频等待而画面镜头尚未完成。

# 二、必须按顺序执行的制作流程

## 阶段 A：脚本解析与时码锁定

1. 完整阅读附件，不要只读取开头。
2. 输出或写入内部制作清单，至少包含下列字段：

| 镜头 | 原始时长 | 画面与动作 | 角色/对白 | 字幕与技术文字 | 音效/音乐 | 状态 |
|---|---:|---|---|---|---|---|

3. 统计总时长，并明确报告：镜头总数、总时长、画幅为 9:16、计划交付分辨率和帧率。
4. 若脚本中存在不清楚、冲突或缺失的关键内容，只针对该具体问题向我提问；其余情况下不要反复确认，直接开始制作。

## 阶段 B：统一视觉设定与角色连续性

1. 先生成或建立一张统一的竖屏风格参考图/角色圣经，固定以下内容：
   - 主角和主要配角的外形、年龄感、服装、发型、表情逻辑；
   - 世界观、场景、时代感、日夜光线、主色、线条与材质；
   - 画面风格必须服务于附件脚本。若脚本指定致敬、科幻、漫画、办公室、悬疑等风格，严格遵守其氛围与构图要求；
   - 所有镜头必须在角色造型、道具、色彩、办公室/城市/技术空间等方面保持连续。
   - **统一视觉设定只用于锁定角色与世界观，不得被误当成每一镜的开场画面模板。** 每个镜头必须以该镜自身分镜规定的景别、场景、人物位置、动作阶段、道具状态和情绪作为独立的视觉起点。
2. 之后生成每个镜头时，都以同一视觉设定作为一致性参考；不要每一镜都变成不相关的角色或画风，更不得把第 01 镜或任意一张参考首帧重复用作后续所有镜头的开头。
3. 建立并持续维护“**镜头状态账本**”：每一镜生成前明确记录本镜首帧应呈现的场景、景别、人物位置、人物姿态、表情、道具、屏幕状态、光线和与上一镜的承接关系。视觉参考仅约束人物一致性；本镜的首帧必须来自该状态账本，而非复用统一参考图或上一镜的首帧。
4. 只有脚本明确指定“重复同一机位/回到开场画面/闪回/循环”时，才允许视觉复用；即便如此，也必须以脚本指定的时点、动作和转场呈现，不能因偷懒而把所有镜头都从同一画面起跑。

## 阶段 C：全部静音视频画面制作

1. 所有镜头均制作成 **9:16 竖屏静音动态画面**，建议统一为至少 `720×1280` 生成，最终输出为 `1080×1920`、`24fps`。
2. **逐镜头首帧规则：** 每一个视频片段的第一个可见画面，必须是该镜头独有的首帧状态，而不是统一角色参考图、全片开场画面、上一镜首帧或视频模型的默认起始画面。生成提示中必须明确描述本镜开场时的“地点 + 景别/机位 + 角色位置 + 正在发生的动作阶段 + 关键道具/屏幕状态 + 光线/情绪”，并注明它与上一镜的承接或反差。
3. 每一镜的动作、景别、镜头运动、转场、构图、屏幕氛围和角色表演必须依据附件，而不是只生成静态插图。
4. 如果视频模型的单次生成上限短于原始镜头时长：
   - 必须将该镜头按连续动作拆分为若干段，例如 11 秒拆为 8 秒 + 3 秒，12 秒拆为 8 秒 + 4 秒，13 秒拆为 10 秒 + 3 秒；
   - 分段之间应保持角色位置、镜头方向、灯光、动作和转场的连续性；
   - 后一分段必须从前一分段的结束状态继续，而不是重新播放该镜的首帧或第 01 镜画面；
   - 后期无缝拼接回脚本规定的完整镜头时长；
   - **绝不以缩短镜头、删动作、默认生成 4 秒来代替。**
5. 每完成一个批次，都必须用实际媒体文件检查以下内容：
   - 文件是否存在；
   - 画幅是否为竖屏；
   - 每段实际时长是否符合预期；
   - 分段合并后是否等于原始镜头时长；
   - 镜头顺序是否正确；
   - **本镜首帧是否符合该镜的状态账本，且与不应重复的上一镜/开场镜在场景、景别、构图、角色位置或动作阶段上存在明确差异；**
   - **本镜末帧是否自然承接下一镜，或是否仅在脚本要求时采用明确转场。**
6. 每完成 4 至 6 个镜头，主动给我发送一次简洁、真实的进度更新，格式固定如下：

| 项目 | 已完成情况 |
|---|---|
| 已完成镜头 | 例如 01–06 / 30 |
| 已核验时长 | 逐镜头或本批次时长 |
| 当前阶段 | 例如“全部为静音画面，未生成视频内置配音” |
| 下一步 | 例如“制作 07–12” |

7. 进度更新只报告已完成并已保存的成果。禁止把“正在等待”、“正在生成音频”、“可能会完成”包装成已完成；如果某项生成确实失败或被中断，应立即说明已完成的部分、失败的具体项和替代方案，不要无声卡住。

## 阶段 D：独立普通话配音、音乐与音效

仅在全部静音视频镜头都完成、拼接顺序和时长都已核验后执行本阶段。

1. **独立中文配音：**
   - 逐镜头或逐角色生成独立音轨，严格朗读附件的原始中文台词和旁白；
   - 多角色场景使用明确的角色标签和不同声线；角色语气必须符合附件中的人物关系和情绪；
   - 使用自然、清晰的标准普通话；技术术语、英文缩写、命令、产品名和包名应在音频提示中明确标注读法；
   - 台词应自然地放在对应镜头的动作和留白中，不能抢台、拖尾到下一镜，必要时通过节奏和静音调整处理；
   - 不要为了塞进时长而删词或改词。如脚本语言密度确实超过镜头容量，先保持原文完整并通过更自然的语速、台词起点或镜头内留白处理，只有必须改写时才征求我的确认。

2. **音乐和音效：**
   - 生成原创、无歌词、可长时播放的背景音乐；音色和情绪需跟随剧情从开场、冲突、解释、推进到结尾钩子变化；
   - 背景音乐必须低于对白，留出清晰的人声频段；
   - 使用附件指定或剧情所需的环境音与转场音效，例如雨声、办公室环境、键盘、抽屉、铃铛、系统提示、机械装置等；
   - 音效不能盖住任何台词，转场不得出现突兀爆音。

3. **字幕与技术文字：**
   - 字幕逐句对应实际台词，采用可读的简体中文字体、足够对比度、合理安全边距；
   - 技术命令、代码、包名、网页地址、产品功能列表、架构标签和风险提示以独立技术文字层叠加，确保可读、可校对；
   - 不让生成模型承担小字渲染；所有关键小字都以标准后期文字层完成。

## 阶段 E：总合成、验收与交付

1. 按附件镜头顺序合成所有画面、独立配音、配乐、音效、字幕和技术文字。
2. 最终必须进行客观技术核验：

| 检查项 | 验收标准 |
|---|---|
| 画幅 | 9:16 竖屏 |
| 主交付分辨率 | 1080×1920 |
| 帧率 | 24fps，或附件明确指定的帧率 |
| 时长 | 等于附件镜头总时长，编码误差不超过 0.5 秒 |
| 镜头完整性 | 所有镜头都存在、顺序正确、无漏镜 |
| 首帧与连续性 | 各镜首帧符合分镜状态账本；除脚本明确复用外，不得重复开场画面、上一镜首帧或统一参考图 |
| 原始时码 | 每一镜或其分段拼接后满足附件时长 |
| 语音 | 独立普通话音轨，无视频内置中文配音 |
| 台词/术语 | 与附件逐字核对，无明显错读、错字、漏读 |
| 字幕 | 与对白同步，关键技术文字可读 |
| 输出文件 | 可正常打开，包含视频和音轨 |

3. 默认交付下列文件：
   - `主交付_字幕版_1080x1920.mp4`：带混音、字幕、技术文字的观看版本；
   - `主交付_无字幕净画面_1080x1920.mp4`：保留混音但不烧录字幕的版本；
   - `完整混音.wav`：与成片同样总时长的独立音频；
   - `中间母版_ProRes422HQ.mov`：供继续后期使用；
   - `字幕工程.ass` 或 `.srt`；
   - `制作清单/时码表.md` 与合成脚本（如有）。
4. 最终只在所有文件生成并经核验后报告“完成”。交付信息需说明实际分辨率、帧率、总时长、镜头数，以及主观看文件的名称。

# 三、绝对禁止事项

- 禁止把长篇分镜漫剧当成 4 秒、6 秒或单镜头试片交付。
- 禁止忽略脚本中明确标注的 6 秒、9 秒、12 秒等时码。
- 禁止因为模型单段上限而压缩剧情；应拆段生成并无缝合并。
- 禁止使用视频生成模型自动生成的中文对白作为最终配音。
- 禁止在前三个镜头尚未完成时长验证前，停在不可见的音频等待阶段。
- 禁止声称“正在进行”却长时间不提供已完成镜头、实际时长和下一步。
- 禁止让模型自动生成关键代码、终端命令和密集技术文字后不校对。
- **禁止把全片开场画面、第 01 镜首帧、统一角色参考图、上一镜首帧或视频模型默认首帧，重复作为每个分镜视频的起始画面。**
- 禁止跳过最终的文件时长、画幅、帧率、音轨和镜头完整性核验。
```

## 这份提示词解决的问题

| 本次暴露的问题 | 模板中的固定规避措施 |
|---|---|
| 长视频被误做成短片或默认 4 秒片段 | 明确“长篇任务”，逐镜头时码优先，原时长不可压缩。 |
| 6、9、12 秒镜头被缩短 | 规定：模型受限时必须拆段生成并无缝拼回原始时长。 |
| 视频内置中文配音存在错读、漏词和音质问题 | 画面全程静音生成；中文音频全部改为独立高质量普通话音轨。 |
| 画面还未完成就停在音频等待阶段 | 强制“先完成全部静音镜头，后做音频”，杜绝阻塞主线。 |
| 用户不知道是否真的在推进 | 要求每 4–6 镜报告一次可验证进度，只汇报已保存成果。 |
| 技术命令和小字容易错误 | 关键文字由字幕/后期文字层叠加，并从脚本文档逐字核对。 |
| 最终文件可能规格不准确 | 强制核验 9:16、1080×1920、24fps、总时长、音轨和镜头完整性。 |
| 每个分镜都重复最初的开场画面 | 将“统一角色/画风参考”与“逐镜头首帧状态”严格分离；建立镜头状态账本；每镜生成前描述独有首帧，生成后强制检查与开场镜、上一镜的差异及转场承接。 |

> **建议：** 后续每次只需上传分镜脚本并粘贴模板即可。若脚本已经很完整，完全不需要另行写一份“剧情提示词”；模板会把附件确立为唯一内容源，同时把工艺、节奏、质量控制和交付规范固定下来。
