## 【本集设定】

- **本集目标**：讲透 deepseek-harness 最重要的结构化设计——能力缝（capability seam）三角色模型，用 shell  seam 这个教科书案例讲清「换实现不改工具」如何成立。
- **研发收获**：掌握 Definition / Provider / Consumer 的分包规则与依赖红线（只依赖 Definition，永不依赖具体 Provider）；理解 `resolve(request): Spec` 的显式默认化模式。
- **领导收获**：理解「合规要求把执行环境迁到沙箱」这类变化，在 dsh 里是一行配置的事，而不是一个季度的重构——架构弹性直接折算成响应成本。
- **故事梗概**：公司安全审计风暴——老师宣布：所有 AI agent 的命令执行必须一周内迁到隔离沙箱，胖虎的「裸奔服务器」被当场点名。小夫幸灾乐祸说大雄的工具层全部要重写。大雄连夜加班，哆啦A梦却带他去喝咖啡：「道具换一枚就好，为什么你觉得我要重做一只手？」
- **出场角色**：大雄、哆啦A梦、老师、小夫、胖虎、出木杉
- **结尾钩子**：迁移顺利完成，但大雄在复盘时发现一个诡异问题：agent 明明执行了命令，重启后却「完全不记得」自己做过什么 → 引出下集会话日志。

### 第 4 页 ｜ 概念页：能力缝的三角色
- **版式**：中心辐射图变体——横向三段式流水线构图，三个角色是三个等距线框「站台」，中间用契约卷轴连接，一条橙色虚线动线贯穿。
- **画面**：三个站台从左到右：Definition（一份发光的契约卷轴 `ctx.shell`）、Provider（两枚道具：「本地竹蜻蜓」「沙箱竹蜻蜓」并排）、Consumer（一个机器人手臂拿着 `bash` 工具）。大雄站在传送带上被带着走。
- **文字**：
  - 标题：一条完整的能力缝 = 三个角色
  - 站台标注：
    - **Service Definition（契约）**：定义服务接口与 `ctx` 键，如 `ctx.shell`；它是 Cordis Service 类，不是 TypeScript interface
    - **Service Provider（实现）**：提供具体后端，可多个互替——本地执行、沙箱执行、PowerShell
    - **Consumer（使用者）**：模型工具、命令、循环——只认契约，不认实现
  - 底部一行结论：三个角色齐备才叫一条缝；少一个，就退化成普通模块。
- **技术点**：三角色模型见 `.agents/notes/implemented/architecture/2026-06-13-capability-seams.md`；「seam 必须完整，永不只交一个角色」是仓库规则。

### 第 8 页 ｜ 深度页：显式默认化 —— resolve 模式
- **版式**：中心辐射图。中心是 `resolve(request): Spec` 的深色代码卡片，向外辐射两条动线：「显式之路」（亮）与「隐式之路」（灰，打叉）。
- **画面**：左侧大雄走亮路：请求先经过一个「默认值裁决所」建筑，出来时变成完整规格单；右侧灰路上有个隐藏陷阱（`?? default` 埋在函数深处）。
- **文字**：
  - 标题：默认值必须站在明处
  - 代码卡片（伪代码）：
    ```ts
    // 契约层：先解析，再执行
    const spec = shell.resolve(request)
    //   ↑ 默认值、校验、归一化，全部在这一步完成
    await shell.run(spec)
    //   ↑ run() 里没有任何隐藏的 ?? default
    ```
  - 要点：包边界的默认化是一个显式的 `resolve(request): Spec` 步骤；藏在 `run()` 里的 `?? default` 是被禁止的隐式行为
  - 气泡（出木杉）：配置错了，在 resolve 阶段就当场报错——这叫「响亮地失败」。
- **技术点**：`dsh-shell` 的 request/spec 分离是仓库「Explicit > implicit at package boundaries」规则的模板；「Misconfiguration fails loud」——配置错误在最早可判定处报错，绝不静默跳过。

### 第 11 页 ｜ 启发页：给你的系统设计三条缝
- **版式**：Z 字形阅读动线，三个编号节点沿 Z 字排布，每个节点配迷你等距图。
- **画面**：出木杉在三个白板间走动讲解；大雄跟在后面记笔记。
- **文字**：
  - 标题：离开 dsh，这个思维也能带走
  - 节点一：**找到你系统里的「执行环境」** —— 凡是可能被合规/成本/性能逼着换的东西，都是候选缝
  - 节点二：**把契约做成资产** —— 契约层只放词汇与规则，不放任何实现细节；契约越稳定，实现越自由
  - 节点三：**让使用者失明** —— Consumer 不知道也不该知道背后是哪个 Provider；知道得越少，系统越柔韧
  - 气泡（出木杉）：好架构不是预测变化，而是给变化预留便宜的出口。
- **技术点**：能力缝是可迁移的架构方法论，不限于本框架。
