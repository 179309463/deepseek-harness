## 【本集设定】

- **本集目标**：讲透 Cordis 内核的五个核心概念——Plugin、Context、inject、类型化事件、可逆副作用（effect），让读者理解「插件系统」与「插件清单」的本质区别。
- **研发收获**：理解 `ctx.effect()` 的可逆语义为什么是热挂载与自动回滚的地基；理解四种事件分发模式（emit / waterfall / parallel / serial）的用途差异。
- **领导收获**：理解「插件化」不是口号而是一套有论文支撑的工程机制——动态装卸不重启、依赖关系自动化、卸载不留垃圾，这些直接对应运维成本与系统稳定性。
- **故事梗概**：接上集。大雄好奇四次元口袋为什么能装下无穷道具、用完还能「收回去」。哆啦A梦把口袋翻过来——里面不是杂物堆，而是一座精密的「道具仓库」：每个道具挂在挂钩上（Context），有编号和依赖标签（inject），拿走道具自动登记、归还自动销账（effect 回滚）。大雄想起自己上周五下班前忘了关测试服务导致周末服务器烧爆的惨痛经历，恍然大悟。
- **出场角色**：大雄、哆啦A梦、出木杉（讲解深度页）
- **结尾钩子**：大雄问「道具有千千万万，换个道具为什么还要改哆啦A梦你自己？」→ 引出下集能力缝三角色。

- **文字**：

### 第 6 页 ｜ 深度页：effect —— 可逆的副作用
- **版式**：对角线分割。左下三角是「挂上」：插件方块插入插槽，登记台自动盖章；右上三角是「卸下」：方块拔出，盖章被自动划掉，一缕青烟表示清理完毕。中间斜切条上是核心代码。
- **画面**：两侧等距小景各一；中间斜切条为深色代码卡片。
- **文字**：
  - 标题：挂上即登记，卸下即回滚
  - 斜切代码卡：
    ```ts
    ctx.effect(() => {
      const dispose = ctx.tools.register(myTool)
      return dispose   // 插件卸载时自动调用
    })
    ```
  - 左侧标注：注册工具 / 监听事件 / 挂 prompt 片段 —— 全部经 `ctx.effect()` 或 `ctx.on()`
  - 右侧标注：插件卸载 / 热更新 → 所有注册自动撤销，不留残留
  - 气泡（大雄）：所以上周五那个服务，如果是插件就会自己关掉？
  - 气泡（哆啦A梦）：拔掉插件的那一刻，它带来的每一点影响都会倒放回去。
- **技术点**：仓库核心约定「Registrations are effects」——一切贡献经 `ctx.effect()` / `ctx.on()` 注册，registry 的 `register()` 返回 disposer；这是 HMR 与动态重组合的语义地基。

### 第 7 页 ｜ 深度页：四种事件，四种对话方式
- **版式**：左侧竖栏（竖排「Events」），右侧纵向四个高度不一的面板（瀑布式错落排布，非均分），每个面板一个迷你场景图。
- **画面**：四个面板分别用小人场景表现：
  - **emit**（广播）：哆啦A梦朝天空喊话，一群插件小人各自听见
  - **waterfall**（瀑布审批）：一份文件沿流水线传递，每人盖章后传给下一人，有人按住文件就停下
  - **parallel**（并行）：四个人同时开工，最后汇总
  - **serial**（串行）：排队逐个执行，一个结束下一个才开始
- **文字**：
  - 标题：插件之间的四种对话方式
  - 面板标注：
    - `emit` 广播通知——发生了什么，不期待回答
    - `waterfall` 逐级委托——每个监听器可选择放行（`next()`）或拦截
    - `parallel` 并行收集——同时问所有人，汇总结果
    - `serial` 串行决策——按顺序逐个商议，如 `agent/turn-stopping`
  - 气泡（胖虎，乱入）：拦下来不就行了！
  - 气泡（出木杉）：waterfall 的监听器不调 `next()` 就是真的拦下来了——这是策略开关，不是 bug。
- **技术点**：四种分发模式是 Cordis 类型化事件的核心；`waterfall` 语义是 dsh 审批/守卫/压缩等策略机制的载体（第 5 集详述）。
