## 【本集设定】

- **本集目标**：讲透两个进阶能力——subagent 委派体系（六种 Provider、深度限制、一次性/可持续会话）与「可移植执行世界」（换 `ctx.fs` + `ctx.subprocess`，bash/终端/LSP 整体迁入 E2B 沙箱）。
- **研发收获**：理解 subagent 缝的多 Provider 并存设计（与 shell 单例不同）；one-shot 与 continuable 两种委派模式；「执行世界」作为一个整体迁移的架构含义。
- **领导收获**：agent 可以分工协作（委派）且可以在隔离环境里干活（沙箱）——前者对应吞吐与专业化，后者对应安全与合规，两者都是规模化落地的前置条件。
- **故事梗概**：季度末交付地狱——静香同时派来三个独立任务（重构模块、写测试、补文档），大雄一个人（一个 agent）根本忙不过来；同时胖虎的「实验性清理脚本」差点把共享服务器上的数据炸了，老师下令 agent 的高危实验一律进隔离环境。哆啦A梦一次掏出两件道具：「分身术」让 agent 学会摇人，「任意门」让所有工具的执行地点整体搬进沙箱。
- **出场角色**：大雄、哆啦A梦、静香、胖虎、老师、出木杉
- **结尾钩子**：深夜，大雄发现 agent 在自己检查自己的插件、还在修改自己的配置——「它在干什么？！」→ 引出下集自修改与记忆压缩。

### 第 4 页 ｜ 深度页：一次性 vs 可持续 —— 两种委派模式
- **版式**：杂志式不对称网格。左侧 3/5 两条对比跑道：「一次性外卖员」（送达即走）与「长期外包团队」（驻场可多轮沟通）；右侧 2/5 深色代码卡片。
- **画面**：左跑道一个小人送完包裹就消失（one-shot：`start()` → 等 `run.result`）；右跑道一个小人坐在工位上，电话线连回主 agent（continuable：`send_message` 续聊 / `interrupt` 打断）。
- **文字**：
  - 标题：派外卖员，还是雇外包团队？
  - 代码卡片（伪代码）：
    ```ts
    // 一次性：交活 → 等结果
    const run = await provider.start(task)
    const result = await run.result
    // 可持续：建立长期会话，随时追加指令
    const h = await provider.startContinuable(task)
    await h.send_message('顺便把测试也补了')
    ```
  - 要点：Provider 声明自己的能力（`outputSchema` / `depthLimit` / `toolFilter` / `persona`），请求超能力范围 → 当场响亮拒绝

- **技术点**：`SubagentRuntime` 在委派前校验 capability 契约；continuable 需 Provider 实现 `prepareContinuable`；控制工具 `send_message` / `interrupt` / `list_agents` 见 `tool-subagent-control`。

### 第 5 页 ｜ 深度页：分身不能无限分 —— maxDepth

- **文字**：

### 第 11 页 ｜ 双受众总结页
- **版式**：上下不对称分割（上 55% 出木杉的笔记，下 45% 老师划重点），中间斜切分隔条。

- **文字**：
  - **出木杉的笔记（给研发）**：
    - subagent 缝：`ctx.subagents` 多 Provider 并存按名选；capability 校验失败即响亮拒绝

    - 安全：隔离环境不是「再搭一套系统」，而是配置层的一次世界迁移
    - 生态：ACP 让异构 agent 产品互相委派——不被单一供应商的执行栈锁死
