# 第 8 集 ｜ 会自我改造的机器人（手机长图漫画版）
## ——自修改运行时（cordis 工具集）与上下文压缩（compaction）

> 使用方式：将本文件**整篇**粘贴给 AnyGen，即可生成本集手机长图漫画。工具须按【逐段脚本】逐段生成 1080px 宽的竖版图片（本集共 12 段），再按【合并与产出规范】垂直无缝拼接为一张长图。全局风格设定已包含在内，无需补充其他提示词。

## 【全局风格设定 · 每集通用，务必严格遵守】

### 成品形态与生成流程
- 最终成品是**一张手机长图漫画**：宽度恒为 **1080px**，垂直向下滚动阅读，**全彩**，高清。
- 不要尝试一次生成整张长图。必须按【逐段脚本】拆成多段分别生成：每段是一张 1080px 宽、高度 1440–2160px 的竖版图片（按内容多少定高，高清渲染）。
- 全部段落生成后，按段序**垂直无缝拼接**为一张完整长图。拼接处不得出现白缝、错位或重复内容。

### 顶部与底部安全区（仅首尾两段）
- 仅在整张长图的**最顶部**留出 ≥200px、**最底部**留出 ≥200px 的安全高度：两处为背景/场景的纯净延展（不是白色边、不放任何人物、文字、道具），用于躲避手机状态栏、刘海屏、标题栏与底部手势区的遮挡。
- 除首尾两段外，其余各段上下边缘**满幅出血**，段与段之间不留任何空隙。
- 每段的上下接缝必须落在斜切格线、场景色块或天空/夜色上，**禁止接缝切过人脸、对话气泡或文字**。

### 画风
藤子·F·不二雄经典哆啦A梦角色形象 + 现代科技杂志编辑插画（editorial illustration）质感。角色为简洁粗线条漫画风，背景与信息图采用扁平化、等距线框、细腻网点纹理。整体是「印刷精美的技术杂志」，不是儿童绘本。全彩画面，高清、锐利、矢量感，2K 分辨率质感，禁止黑白稿与低分辨率感。

### 统一色板
主色哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`；底色米白纸感 `#FAF6EE`；强调橙 `#FF8C42`；正文墨黑 `#222222`。架构图使用蓝白线框 + 橙色高亮关键路径；代码一律深色终端卡片（`#1E1E2E` 底、浅色等宽字）。夜景与情绪场景可用深蓝渐变，但每段都必须保持彩色。

### 角色锚点（每集造型必须一致）
- 哆啦A梦：蓝色机器猫，白肚皮，红项圈黄铃铛，四次元口袋，表情睿智从容
- 大雄：黄 T 恤、蓝短裤、圆眼镜，初级程序员，工牌写着「野比科技」，常背双肩包
- 出木杉：白衬衫，端正沉稳，手持平板或指向架构图
- 小夫：绿色上衣、尖嘴，爱炫耀，常拿手机秀自己的项目
- 胖虎：橙色条纹衫，体格壮，撸袖子，「大力出奇迹」做派
- 静香：粉色裙子，产品经理气质，拿需求文档
- 老师：深色西装，严肃但公正，部门技术总监

### 动态分镜规则（长图的灵魂）
1. **禁止横平竖直的均分宫格**。每段 3–5 格，格子大小错落，主格占该段画面的 40–60%。
2. 格线必须动起来：斜切面板、锯齿/闪电形分割线、弧形格、梯形格交替使用；允许「破格」——角色、道具或光效探出格线 10–20%，制造冲击力。
3. 阅读动线永远自上而下：用斜切格线的指向、虚线动线、角色视线与色块流向，把视线从每段顶部引到底部，再自然滚入下一段。
4. 版式库（每段从中组合选择，禁止连续两段使用同一版式）：斜切双格、上大下小锯齿分割、出血大图 + 浮动旁白框、左窄右宽梯形双格、纵向时间轴三格、中心辐射、Z 字动线三格、满宽全景格。
5. **画面必须充实**：每一格都要有具体场景环境（办公室、会议室、深夜街道、全息空间……）、角色动作或信息图，禁止大面积空白背景，禁止「一格一个人头 + 一句话」的敷衍构图。
6. 角色在单格内不超过画面 1/2，以全身/半身的场景化姿态出现（坐着敲代码、站在白板前、围着工位）；禁止大头像特写撑满整格。
7. 每段保留一个「视觉钩子」：一道斜切色块、一个出血的道具、一条贯穿的虚线动线、一片发光特效。

### 文字规则（手机阅读的生命线）
1. 全部使用中文，技术术语保留英文原词（如 plugin、loop、session）。
2. 字号按 1080px 宽画面计，必须大且清晰：封面主标题 96–120px；剧情小节题字 64–80px；旁白框与正文 40–48px；对话气泡 40–44px；最小的图注标注也不得小于 32px。
3. 对话气泡每句不超过 20 字，但每格可以放 2–4 个气泡形成对话回合，让故事娓娓道来。
4. 旁白一律用漫画式色块旁白框（米白底或深蓝底白字），贴在格子的上缘或下缘；禁止整段文字墙，禁止一段全是字没有画面。
5. **禁止出现任何页码与编号文字**：不写「第 X 页」「第 X 段」「第 X 格」，不写 01、02 之类的序号。剧情衔接用手写感题字（如「当天深夜」「周五下午」）或纯场景过场格。
6. 架构图采用等距线框风格，节点用圆角矩形/圆柱体，箭头标注数据流，关键路径橙色高亮；架构图必须**纵向分层**（自上而下），角色站在图旁的瞭望台或地面上仰望、指点。
7. 代码/伪代码用深色终端卡片，带行号和语法高亮，卡片一角可有迷你角色注释气泡；卡片上的代码必须与脚本所写**逐字一致**。

### 屏幕呈现规则
- **禁止出现浏览器或 Windows/macOS 窗口外框**：不要地址栏、标题栏、红绿灯按钮、窗口边框。
- 所有屏幕内容一律以悬浮全息面板、深色终端卡片、发光卷轴、数据流光带的形式融入漫画场景。

### 完整结构（必须有头有尾）
- **第 1 段 = 封面（顶部标题区域）**：系列题字「哆啦A梦讲 deepseek-harness」+ 本集主标题 + 副标题 + 主视觉画面 + 顶部安全区。
- **中间各段 = 正文**：连续剧情，一气呵成，不分页、无页码。
- **最后 1 段 = 结尾页（尾部结束区域）**：本集收束画面 + 「本集完」题字 + 下集预告 + 底部安全区。

### 禁止事项
- 禁止角色占满画面、大头像特写、低分辨率感
- 禁止整段纯文字或整段纯插图
- 禁止无剧情动机的生硬说教
- 禁止四宫格式平均切分、横平竖直的宫格
- 禁止页码、段号、格号等编号文字
- 禁止浏览器/操作系统窗口外框
- 禁止大面积空白、稀疏敷衍的画面
- 禁止任何小于 32px 的文字
- 禁止黑白稿，必须全彩

## 【本集设定】

- **本集目标**：讲透两个最能体现 dsh 架构自信的能力——agent 检查/挂载自己的插件（自修改运行时），以及上下文压缩（compaction）如何让长任务不「撑死」。
- **研发收获**：掌握 `cordis_inspect / cordis_define / cordis_run / cordis_stop / cordis_undefine` 五件套的语义与边界（进程内存、重启即失、vm 沙箱不是安全边界）；理解 compaction-basic 的 pre-step 压力检测、`surfaceOp: replace` 摘要替换与 context-overflow 溢出恢复。
- **领导收获**：自修改 = 系统可在运行中被 agent 自己扩展（效率上限），但它的边界被明确划出（安全下限）；压缩 = 长任务成本可控，token 预算不失速。
- **故事梗概**：承接上集深夜异象——大雄发现 agent 在「自检」。哆啦A梦淡定解释：这是它与生俱来的内省能力，就像机器人可以打开自己的检修盖。随后大雄让 agent 临时造一个「报表美化」小插件现场试验；下午长任务跑到一半上下文濒临爆表，哆啦A梦再演示「记忆压缩」——把吃撑的记忆面包压成一口大小的精华方块。
- **出场角色**：大雄、哆啦A梦、出木杉、胖虎（想把自修改当武器被拦）、老师（关心边界）
- **结尾钩子**：能力都齐了，老师问出终极问题——「这套东西，怎么接进公司现有的系统？值不值得全面铺开？」→ 引出大结局：协议、SDK 与落地路线图。

### 第 3 段 ｜ 概念：自修改五件套
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在全息光雾，下接缝落在色块底边。
- **版式**：中心辐射——主格占 55%，中心是 agent 发光体，五件工具如手术器械环绕排布（扇形错落，非均分）。
- **画面**：
  - 格 1（主格）：全息手术室场景，中央 agent 发光体悬浮，五件发光器械环绕：放大镜（inspect）、图纸（define）、启动钥匙（run）、停止阀（stop）、碎纸机（undefine）。哆啦A梦戴着手套逐一介绍，大雄戴着安全帽认真记。
  - 格 2（中部标注格，米白底，五条器械标注自上而下排列）：`cordis_inspect`——只读检查：服务、fiber、工具、动态包一览无余；`cordis_define`——登记定义：语法检查后入库，**只登记，不运行**；`cordis_run`——运行：host 半在 vm 沙箱求值，browser 半广播到打开的页面；`cordis_stop`——卸载运行态：定义保留，可再 run；`cordis_undefine`——停止并遗忘：定义一并移除。

- **技术点**：五件套语义见 `packages/extensions/tool-cordis/README.md`；host 侧经 `node:vm` 沙箱执行，browser 侧广播到客户端。

### 第 4 段 ｜ 深度：三条边界 —— 自修改的安全说明书
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在警示条纹色块，下接缝落在红色虚线。
- **版式**：纵向时间轴三格变体——三张错落卡片自上而下纵向排列（高度不一），左侧一条警示条纹竖带贯穿。
- **画面**：
  - 格 1（卡片一）：内存芯片图标发光。**进程内存**——动态插件活在内存里，不写 `cordis.yml`、不落磁盘。
  - 格 2（卡片二）：时钟图标。**重启即失**——重启进程，一切动态定义烟消云散（想持久化？请走正规插件包）。
  - 格 3（卡片三）：虚线围栏图标。**vm ≠ 安全边界**——`node:vm` 隔离了全局变量，但不防恶意代码；它的定位像 bash——强大，但要在审批与沙箱的框架内使用。胖虎撸着袖子想冲过卡片前的一道红色虚线，被拦下。
  - 格 4（底部对话格）：气泡（胖虎）：「让它给自己写个无敌外挂！」气泡（哆啦A梦）：「它是手术刀，不是许愿机——」「手术室门口站着第 5、6 集的审批闸门。」
- **旁白框**（贴格 1 上缘，深蓝底白字）：能力越大，边界越要刻在脸上。
- **技术点**：三条边界出自 `tool-cordis` 设计文档；动态插件跨 turn 存活但重启即失，与持久插件（cordis.yml）是两条路径。

### 第 5 段 ｜ 剧情：现场造一个插件
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在终端卡片边缘，下接缝落在灯泡光效。

    ```ts
    // ③ 下班前 stop——痕迹随进程消失
    ```
    卡片上方悬浮发光题字：三分钟，它给自己造了件新装备。
  - 格 2（左下梯形格）：办公室里，agent 的全息形象头顶亮起一个新装备图标（如灯泡点亮），大雄目瞪口呆，手里的报表正被自动美化成漂亮的版式。

### 第 6 段 ｜ 剧情转折：吃撑的记忆面包
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在蛇身鳞光，下接缝落在仪表盘卡片边缘。
