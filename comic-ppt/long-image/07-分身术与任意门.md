## 【全局风格设定 · 每集通用，务必严格遵守】

### 成品形态与生成流程
- 最终成品是**一张手机长图漫画**：宽度恒为 **1080px**，垂直向下滚动阅读，**全彩**，高清。
- 不要尝试一次生成整张长图。必须按【逐段脚本】拆成多段分别生成：每段是一张 1080px 宽、高度 1440–2160px 的竖版图片（按内容多少定高，高清渲染）。
- 全部段落生成后，按段序**垂直无缝拼接**为一张完整长图。拼接处不得出现白缝、错位或重复内容。

### 顶部与底部安全区（仅首尾两段）
- 仅在整张长图的**最顶部**留出 ≥200px、**最底部**留出 ≥200px 的安全高度：两处为背景/场景的纯净延展（不是白色边、不放任何人物、文字、道具），用于躲避手机状态栏、刘海屏、标题栏与底部手势区的遮挡。
- 除首尾两段外，其余各段上下边缘**满幅出血**，段与段之间不留任何空隙。
- 每段的上下接缝必须落在斜切格线、场景色块或天空/夜色上，**禁止接缝切过人脸、对话气泡或文字**。

### 画风
藤子·F·不二雄经典哆啦A梦角色形象 + 现代科技杂志编辑插画（editorial illustration）质感。角色为简洁粗线条漫画风，背景与信息图采用扁平化、等距线框、细腻网点纹理。整体是「印刷精美的技术杂志」，不是儿童绘本。全彩画面，高清、锐利、矢量感，2K 分辨率质感，禁止黑白稿与低分辨率感。

### 统一色板
主色哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`；底色米白纸感 `#FAF6EE`；强调橙 `#FF8C42`；正文墨黑 `#222222`。架构图使用蓝白线框 + 橙色高亮关键路径；代码一律深色终端卡片（`#1E1E2E` 底、浅色等宽字）。夜景与情绪场景可用深蓝渐变，但每段都必须保持彩色。

### 角色锚点（每集造型必须一致）
- 哆啦A梦：蓝色机器猫，白肚皮，红项圈黄铃铛，四次元口袋，表情睿智从容
- 大雄：黄 T 恤、蓝短裤、圆眼镜，初级程序员，工牌写着「野比科技」，常背双肩包
- 出木杉：白衬衫，端正沉稳，手持平板或指向架构图
- 小夫：绿色上衣、尖嘴，爱炫耀，常拿手机秀自己的项目
- 胖虎：橙色条纹衫，体格壮，撸袖子，「大力出奇迹」做派
- 静香：粉色裙子，产品经理气质，拿需求文档
- 老师：深色西装，严肃但公正，部门技术总监

### 动态分镜规则（长图的灵魂）
1. **禁止横平竖直的均分宫格**。每段 3–5 格，格子大小错落，主格占该段画面的 40–60%。
2. 格线必须动起来：斜切面板、锯齿/闪电形分割线、弧形格、梯形格交替使用；允许「破格」——角色、道具或光效探出格线 10–20%，制造冲击力。
3. 阅读动线永远自上而下：用斜切格线的指向、虚线动线、角色视线与色块流向，把视线从每段顶部引到底部，再自然滚入下一段。
4. 版式库（每段从中组合选择，禁止连续两段使用同一版式）：斜切双格、上大下小锯齿分割、出血大图 + 浮动旁白框、左窄右宽梯形双格、纵向时间轴三格、中心辐射、Z 字动线三格、满宽全景格。
5. **画面必须充实**：每一格都要有具体场景环境（办公室、会议室、深夜街道、全息空间……）、角色动作或信息图，禁止大面积空白背景，禁止「一格一个人头 + 一句话」的敷衍构图。
6. 角色在单格内不超过画面 1/2，以全身/半身的场景化姿态出现（坐着敲代码、站在白板前、围着工位）；禁止大头像特写撑满整格。
7. 每段保留一个「视觉钩子」：一道斜切色块、一个出血的道具、一条贯穿的虚线动线、一片发光特效。

### 文字规则（手机阅读的生命线）
1. 全部使用中文，技术术语保留英文原词（如 plugin、loop、session）。
2. 字号按 1080px 宽画面计，必须大且清晰：封面主标题 96–120px；剧情小节题字 64–80px；旁白框与正文 40–48px；对话气泡 40–44px；最小的图注标注也不得小于 32px。
3. 对话气泡每句不超过 20 字，但每格可以放 2–4 个气泡形成对话回合，让故事娓娓道来。
4. 旁白一律用漫画式色块旁白框（米白底或深蓝底白字），贴在格子的上缘或下缘；禁止整段文字墙，禁止一段全是字没有画面。
5. **禁止出现任何页码与编号文字**：不写「第 X 页」「第 X 段」「第 X 格」，不写 01、02 之类的序号。剧情衔接用手写感题字（如「当天深夜」「周五下午」）或纯场景过场格。
6. 架构图采用等距线框风格，节点用圆角矩形/圆柱体，箭头标注数据流，关键路径橙色高亮；架构图必须**纵向分层**（自上而下），角色站在图旁的瞭望台或地面上仰望、指点。
7. 代码/伪代码用深色终端卡片，带行号和语法高亮，卡片一角可有迷你角色注释气泡；卡片上的代码必须与脚本所写**逐字一致**。

### 屏幕呈现规则
- **禁止出现浏览器或 Windows/macOS 窗口外框**：不要地址栏、标题栏、红绿灯按钮、窗口边框。
- 所有屏幕内容一律以悬浮全息面板、深色终端卡片、发光卷轴、数据流光带的形式融入漫画场景。

### 完整结构（必须有头有尾）
- **第 1 段 = 封面（顶部标题区域）**：系列题字「哆啦A梦讲 deepseek-harness」+ 本集主标题 + 副标题 + 主视觉画面 + 顶部安全区。
- **中间各段 = 正文**：连续剧情，一气呵成，不分页、无页码。
- **最后 1 段 = 结尾页（尾部结束区域）**：本集收束画面 + 「本集完」题字 + 下集预告 + 底部安全区。

- 禁止整段纯文字或整段纯插图
- 禁止无剧情动机的生硬说教
- 禁止四宫格式平均切分、横平竖直的宫格

- 禁止浏览器/操作系统窗口外框
- 禁止大面积空白、稀疏敷衍的画面

## 【本集设定】

- **本集目标**：讲透两个进阶能力——subagent 委派体系（六种 Provider、深度限制、一次性/可持续会话）与「可移植执行世界」（换 `ctx.fs` + `ctx.subprocess`，bash/终端/LSP 整体迁入 E2B 沙箱）。
- **研发收获**：理解 subagent 缝的多 Provider 并存设计（与 shell 单例不同）；one-shot 与 continuable 两种委派模式；「执行世界」作为一个整体迁移的架构含义。
- **领导收获**：agent 可以分工协作（委派）且可以在隔离环境里干活（沙箱）——前者对应吞吐与专业化，后者对应安全与合规，两者都是规模化落地的前置条件。
- **故事梗概**：季度末交付地狱——静香同时派来三个独立任务（重构模块、写测试、补文档），大雄一个人（一个 agent）根本忙不过来；同时胖虎的「实验性清理脚本」差点把共享服务器上的数据炸了，老师下令 agent 的高危实验一律进隔离环境。哆啦A梦一次掏出两件道具：「分身术」让 agent 学会摇人，「任意门」让所有工具的执行地点整体搬进沙箱。
- **出场角色**：大雄、哆啦A梦、静香、胖虎、老师、出木杉
- **结尾钩子**：深夜，大雄发现 agent 在自己检查自己的插件、还在修改自己的配置——「它在干什么？！」→ 引出下集自修改与记忆压缩。

### 第 3 段 ｜ 概念：subagent —— 会摇人的 agent
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在全息光雾，下接缝落在斜切格线。
- **版式**：中心辐射——主格占 55%，中心是主 agent 发光体，向外辐射六条不同颜色的线，各连一个 Provider 方块（分两圈错落排布，绝不均分）。
- **画面**：
  - 格 1（主格）：全息空间里，中央一个发光的 agent 核心体悬浮，六条光线向外辐射：内圈两个方块标注 `spawn`（全新会话，干净上下文）、`fork`（继承父会话历史）；外圈四个方块标注 `acp`、`codex`、`claude-code`、`dsh-sdk`。大雄站在核心体旁举着手机打电话「摇人」，表情惊讶。
  - 格 2（左下标注格，米白底信息卡）：图注——进程内：`spawn` / `fork`；进程外：`acp` / `codex` / `claude-code` / `dsh-sdk`——别的产品也能当你的下属。与 shell 缝不同：多个 Provider **同时并存**，按名字点名派遣。
  - 格 3（右下对话格）：气泡（大雄）：「它还能指挥 Claude Code 干活？！」气泡（哆啦A梦）：「在 dsh 眼里，」「任何会干活的 agent 都是一种 Provider。」
- **技术点**：`ctx.subagents` 支持多 Provider 并存按名选择；六种 Provider 见 `packages/subagent/` 目录。

### 第 4 段 ｜ 深度：一次性 vs 可持续 —— 两种委派模式
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在跑道光带，下接缝落在终端卡片边缘。
- **版式**：上大下小锯齿分割——上部两条上下排列的对比跑道（长度不一），下部满宽深色代码卡片格。
- **画面**：
  - 格 1（上跑道）：「一次性外卖员」——一个小人骑车送完包裹就原地消失成光点。标注：one-shot——交活 → 等结果，送达即走。
  - 格 2（下跑道，更长）：「长期外包团队」——一个小人坐在工位上，一根电话线连回画面外的主 agent，桌上堆着多轮沟通的文件。标注：continuable——建立长期会话，随时追加指令（`send_message` 续聊 / `interrupt` 打断）。
  - 格 3（底部深色终端卡片格，带行号语法高亮）：
    ```ts
    // 一次性：交活 → 等结果
    const run = await provider.start(task)
    const result = await run.result
    // 可持续：建立长期会话，随时追加指令
    const h = await provider.startContinuable(task)
    await h.send_message('顺便把测试也补了')
    ```
    卡片右下角迷你出木杉注释气泡：「能力校验失败是 loud failure，」「绝不会派一个不会干活的人还假装在干。」
- **旁白框**（贴格 1 上缘，深蓝底白字）：Provider 声明自己的能力（`outputSchema` / `depthLimit` / `toolFilter` / `persona`），请求超能力范围 → 当场响亮拒绝。
- **技术点**：`SubagentRuntime` 在委派前校验 capability 契约；continuable 需 Provider 实现 `prepareContinuable`；控制工具 `send_message` / `interrupt` / `list_agents` 见 `tool-subagent-control`。

### 第 5 段 ｜ 深度：分身不能无限分 —— maxDepth
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在树冠光效，下接缝落在地面色块。
- **版式**：出血大图 + 浮动标注卡——主格占 60%，一棵纵向生长的委派树贯穿画面。
- **画面**：
  - 格 1（主格）：一棵自上而下的委派树全息图：主 agent → 子 agent → 孙 agent，每层小人变小一号；树旁一把发光标尺，第三层处横着一道橙色「闸门线」，再往下的小人被光墙弹回。胖虎蹲在树底拿着笔想画第四层，哆啦A梦按住他的笔。
  - 格 2（左上标注卡，米白底）：委派树的默认深度上限是 3。没有深度缰绳的递归委派 = 没有停止条件的递归函数。并行委派走工具并发池（第 5 集的管线纪律同样生效）。
  - 格 3（底部对话格）：气泡（胖虎）：「无限分身，干翻全公司的 backlog！」气泡（哆啦A梦）：「每个分身都在烧 token 和配额。」「缰绳不是限制能力，是保护预算。」
- **技术点**：深度限制默认 `maxDepth: 3`；并行委派复用工具管线的 exclusive/parallel 调度。
