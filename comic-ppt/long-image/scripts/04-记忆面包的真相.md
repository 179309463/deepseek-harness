## 【全局风格设定 · 每集通用，务必严格遵守】

### 成品形态与生成流程
- 最终成品是**一张手机长图漫画**：宽度恒为 **1080px**，垂直向下滚动阅读，**全彩**，高清。
- 不要尝试一次生成整张长图。必须按【逐段脚本】拆成多段分别生成：每段是一张 1080px 宽、高度 1440–2160px 的竖版图片（按内容多少定高，高清渲染）。
- 全部段落生成后，按段序**垂直无缝拼接**为一张完整长图。拼接处不得出现白缝、错位或重复内容。

### 顶部与底部安全区（仅首尾两段）
- 仅在整张长图的**最顶部**留出 ≥200px、**最底部**留出 ≥200px 的安全高度：两处为背景/场景的纯净延展（不是白色边、不放任何人物、文字、道具），用于躲避手机状态栏、刘海屏、标题栏与底部手势区的遮挡。
- 除首尾两段外，其余各段上下边缘**满幅出血**，段与段之间不留任何空隙。
- 每段的上下接缝必须落在斜切格线、场景色块或天空/夜色上，**禁止接缝切过人脸、对话气泡或文字**。

### 画风
藤子·F·不二雄经典哆啦A梦角色形象 + 现代科技杂志编辑插画（editorial illustration）质感。角色为简洁粗线条漫画风，背景与信息图采用扁平化、等距线框、细腻网点纹理。整体是「印刷精美的技术杂志」，不是儿童绘本。全彩画面，高清、锐利、矢量感，2K 分辨率质感，禁止黑白稿与低分辨率感。

### 统一色板
主色哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`；底色米白纸感 `#FAF6EE`；强调橙 `#FF8C42`；正文墨黑 `#222222`。架构图使用蓝白线框 + 橙色高亮关键路径；代码一律深色终端卡片（`#1E1E2E` 底、浅色等宽字）。夜景与情绪场景可用深蓝渐变，但每段都必须保持彩色。

### 角色锚点（每集造型必须一致）
- 哆啦A梦：蓝色机器猫，白肚皮，红项圈黄铃铛，四次元口袋，表情睿智从容
- 大雄：黄 T 恤、蓝短裤、圆眼镜，初级程序员，工牌写着「野比科技」，常背双肩包
- 出木杉：白衬衫，端正沉稳，手持平板或指向架构图
- 小夫：绿色上衣、尖嘴，爱炫耀，常拿手机秀自己的项目
- 胖虎：橙色条纹衫，体格壮，撸袖子，「大力出奇迹」做派
- 静香：粉色裙子，产品经理气质，拿需求文档
- 老师：深色西装，严肃但公正，部门技术总监

### 动态分镜规则（长图的灵魂）
1. **禁止横平竖直的均分宫格**。每段 3–5 格，格子大小错落，主格占该段画面的 40–60%。
2. 格线必须动起来：斜切面板、锯齿/闪电形分割线、弧形格、梯形格交替使用；允许「破格」——角色、道具或光效探出格线 10–20%，制造冲击力。
3. 阅读动线永远自上而下：用斜切格线的指向、虚线动线、角色视线与色块流向，把视线从每段顶部引到底部，再自然滚入下一段。
4. 版式库（每段从中组合选择，禁止连续两段使用同一版式）：斜切双格、上大下小锯齿分割、出血大图 + 浮动旁白框、左窄右宽梯形双格、纵向时间轴三格、中心辐射、Z 字动线三格、满宽全景格。
5. **画面必须充实**：每一格都要有具体场景环境（办公室、会议室、深夜街道、全息空间……）、角色动作或信息图，禁止大面积空白背景，禁止「一格一个人头 + 一句话」的敷衍构图。
6. 角色在单格内不超过画面 1/2，以全身/半身的场景化姿态出现（坐着敲代码、站在白板前、围着工位）；禁止大头像特写撑满整格。
7. 每段保留一个「视觉钩子」：一道斜切色块、一个出血的道具、一条贯穿的虚线动线、一片发光特效。

### 文字规则（手机阅读的生命线）
1. 全部使用中文，技术术语保留英文原词（如 plugin、loop、session）。
2. 字号按 1080px 宽画面计，必须大且清晰：封面主标题 96–120px；剧情小节题字 64–80px；旁白框与正文 40–48px；对话气泡 40–44px；最小的图注标注也不得小于 32px。
3. 对话气泡每句不超过 20 字，但每格可以放 2–4 个气泡形成对话回合，让故事娓娓道来。
4. 旁白一律用漫画式色块旁白框（米白底或深蓝底白字），贴在格子的上缘或下缘；禁止整段文字墙，禁止一段全是字没有画面。
5. **禁止出现任何页码与编号文字**：不写「第 X 页」「第 X 段」「第 X 格」，不写 01、02 之类的序号。剧情衔接用手写感题字（如「当天深夜」「周五下午」）或纯场景过场格。
6. 架构图采用等距线框风格，节点用圆角矩形/圆柱体，箭头标注数据流，关键路径橙色高亮；架构图必须**纵向分层**（自上而下），角色站在图旁的瞭望台或地面上仰望、指点。
7. 代码/伪代码用深色终端卡片，带行号和语法高亮，卡片一角可有迷你角色注释气泡；卡片上的代码必须与脚本所写**逐字一致**。

### 屏幕呈现规则
- **禁止出现浏览器或 Windows/macOS 窗口外框**：不要地址栏、标题栏、红绿灯按钮、窗口边框。
- 所有屏幕内容一律以悬浮全息面板、深色终端卡片、发光卷轴、数据流光带的形式融入漫画场景。

### 完整结构（必须有头有尾）
- **第 1 段 = 封面（顶部标题区域）**：系列题字「哆啦A梦讲 deepseek-harness」+ 本集主标题 + 副标题 + 主视觉画面 + 顶部安全区。
- **中间各段 = 正文**：连续剧情，一气呵成，不分页、无页码。
- **最后 1 段 = 结尾页（尾部结束区域）**：本集收束画面 + 「本集完」题字 + 下集预告 + 底部安全区。

### 禁止事项
- 禁止角色占满画面、大头像特写、低分辨率感
- 禁止整段纯文字或整段纯插图
- 禁止无剧情动机的生硬说教
- 禁止四宫格式平均切分、横平竖直的宫格
- 禁止页码、段号、格号等编号文字
- 禁止浏览器/操作系统窗口外框
- 禁止大面积空白、稀疏敷衍的画面
- 禁止任何小于 32px 的文字
- 禁止黑白稿，必须全彩

## 【本集设定】

- **本集目标**：讲透 dsh 最深刻的一条设计原则——「model-visible ⟺ logged」（凡模型可见，必可从日志重建），以及 SessionEvent 日志、surface 投影、持久化体系。
- **研发收获**：理解 `deriveMessages()` 为什么是模型历史的唯一来源；`SessionEventMap` 的 declaration merging 扩展方式；surfaceOp（append/replace）语义；`SESSION_FORMAT_VERSION = 0` 的预发布立场。
- **领导收获**：agent 的「每一次思考与行动」都有完整审计轨迹——这不是日志功能，而是合规、回溯、计费与事故定责的基础设施。
- **故事梗概**：承接上集——迁移沙箱后，大雄发现 agent 重启后「失忆」了：明明执行过的命令，问它却一脸茫然。大雄想起哆啦A梦的记忆面包，偷偷把「记忆」喂给 agent 的内存变量，结果进程一重启又全没了。哆啦A梦这才揭示真相：在 dsh 里，记忆不在任何「脑子」（内存对象）里，而在一条只增不改的日志里——模型看到的每一段历史，都是日志现场投影出来的。
- **出场角色**：大雄、哆啦A梦、出木杉、静香（提问「那用户删掉的对话呢」）
- **结尾钩子**：大雄问「日志里这些事件，是按什么顺序、被谁写出来的？」→ 引出下集 agent loop 主循环。

## 【逐段脚本】

### 第 1 段 ｜ 封面：记忆面包的真相
- **画布**：1080 × 2160px。本段是全图第 1 段：**顶部 ≥200px 为安全区**（深夜蓝天空的纯净延展，无人物、无文字、无道具）；下缘满幅出血，与第 2 段无缝衔接。
- **版式**：整幅出血主视觉 + 浮动标题字，竖向三层——上部安全区与夜空 → 中部标题区 → 下部主视觉场景。
- **画面**：顶部 200px 是渐变的深夜蓝夜空（纯净无物）。其下进入场景：一片巨大的记忆面包被掰开，断面里不是面包瓤，而是发光的日志事件流——一行行 JSON 光线如星河般流出，出血到画面右边缘。哆啦A梦举着掰开的记忆面包，大雄凑近看断面里的光流，两人体型合计约占画面 1/4。
- **文字**：
  - 标题区（夜空与主视觉之间）：系列题字「哆啦A梦讲 deepseek-harness」（48px，手写感）；主标题「记忆面包的真相」（约 110px，深蓝粗体白描边）；副标题「SessionEvent 日志——模型可见的一切，必须可重建」（44px）；角标小字「第 4 集 · 记忆篇」（36px）。
  - 旁白框（画面下缘，深蓝底白字）：记忆不在脑子里，在一条只增不改的日志里。
- **技术点**：会话日志实现见 `packages/core/session/`，持久化见 `packages/session/`。

- **版式**：对角线分割——左上「昨天」暖色、右下「今天」冷色，大雄站在中间斜切线上。

  - 格 2（右下三角）：题字「今天，重启之后」。同一个面板，冷色调，上面只有一行字：「抱歉，我没有相关记录。」

### 第 3 段 ｜ 剧情：大雄的「记忆面包」方案翻车
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在面包光效，下接缝落在重启的闪光。
- **版式**：Z 字动线四格——大小错落递减，最后一格闪光爆炸效果。
- **画面**：
  - 格 1（左上大格）：大雄往代码里塞全局变量「记忆面包」——把面包形状的变量图标推进代码深处，一脸得意。气泡（大雄）：「我把历史都存进 `memory` 数组了！」
  - 格 2（右上格）：agent 对答如流，全息面板上问答流畅，大雄比出胜利手势。
  - 格 3（中部斜切标注条）：塞内存变量 → 一切正常 → 进程重启，灰飞烟灭。
  - 格 4（底部大格）：进程重启图标一闪，面包「啪」地消失，agent 再次失忆，大雄石化，背景服务器冒烟。气泡（哆啦A梦）：「内存是工作台，不是仓库。工作台每天都会清空。」
- **技术点**：易失内存状态 vs 持久化事件日志，是「玩具 agent」与「产品 agent」的分水岭之一。

### 第 4 段 ｜ 概念：只增不改的事件日志
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在河面光带，下接缝落在禁止修改印章边缘。
- **版式**：出血大图——一条发光的日志长河自上而下纵向流淌（纵向版时间轴），事件卡片顺流而下；哆啦A梦和大雄站在河边。
- **画面**：
  - 格 1（主格，约 70%）：题字「SessionEvent Log——只增不改的时间之河」。一条发光的河从画面顶部流到底部，河上漂着事件卡片：`turn/start`、`user/message`、`assistant/message`、`tool/call`、`tool/result`、`step/end`……已流过的上游河面盖着一个红色「禁止修改」印章；哆啦A梦往河里放了一张新卡片。
  - 格 2（要点卡，米白底）：每一轮对话、每一次工具调用、每一个决策，都是一条不可变事件；事件只能追加（append-only），永不修改、永不删除；重启 = 把日志重新读一遍，「它」就回来了。
  - 格 3（对话格）：气泡（大雄）：「所以『记忆』不是状态，是历史？」气泡（哆啦A梦）：「状态是历史的投影。历史才是真相。」
- **技术点**：`core/session` 是 append-only 的 `SessionEvent` 日志 + 内存 store（`ctx.sessions`）；重启恢复 = 重放日志。

### 第 5 段 ｜ 深度：事件地图 SessionEventMap
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在族谱树冠，下接缝落在出木杉的指示棒。
- **版式**：出血族谱图主格（70%）+ 要点与对话格——事件族谱自上而下分三类分支，三种线型区分。
- **画面**：
  - 格 1（主格）：题字「日志里到底记了什么」。一棵纵向展开的发光「事件族谱」树——生命周期分支：`turn/start`、`turn/end`、`step/start`、`step/end`；消息分支：`user/message`、`assistant/chunk`、`assistant/message`；工具分支：`tool/call`、`tool/result`；根部还有一块橙色高亮的「请求现场」节点：`request/header`（system prompt、工具 schema、配置快照）。出木杉用指示棒点着 `request/header` 节点。
  - 格 2（要点卡）：连「这次请求带了哪些工具和 system prompt」都记——否则无法重建模型看到的现场。
  - 格 3（对话格）：气泡（出木杉）：「审计 agent 的决策，需要『它当时看到了什么』，不只是『它说了什么』。」
- **技术点**：核心事件定义见 `packages/core/session/src/types.ts` 的 `SessionEventMap`；`request/header`、`request/context` 记录请求前缀，在 `deriveMessages()` 之外前置，不重复占用消息历史。

### 第 6 段 ｜ 深度：surface —— 从日志投影出模型历史
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在事件流，下接缝落在胶片光带。
- **版式**：纵向流水线——上方「完整日志」密集事件流 → 中间发光「投影机」→ 下方「模型看到的历史」简洁序列，橙色高亮投影机。
- **画面**：
  - 格 1（上部格）：密集的事件流从顶部涌下，标注「完整日志：几百条事件」。
  - 格 2（中部主格）：题字「模型看到的历史，是日志的投影」。一台发光的等距线框「投影机」（`deriveMessages()`）把密集事件流过滤成干净的三色消息序列——user 蓝 / assistant 白 / tool-result 橙；大雄站在投影机出片口接着「胶片」。
  - 格 3（要点 + 对话格）：要点——能进入模型历史的只有三种 surface 事件：`user/message`、`assistant/message`、`tool/result`；每个 surface 事件携带 `surfaceOp`：`append`（追加）或 `replace`（替换一段区间）；`session.deriveMessages()` 是唯一投影入口。气泡（大雄）：「所以不存在『偷偷塞给模型一句话』？」气泡（哆啦A梦）：「塞进去的东西必须先写进日志，否则下一条规则会拦住你。」
- **技术点**：surface 机制见 `packages/core/session/src/surface.ts`；`deriveMessages()` 见 `packages/core/session/src/index.ts`。

### 第 7 段 ｜ 铁律：model-visible ⟺ logged
- **画布**：1080 × 1680px。上下缘满幅出血；上接缝落在徽章光芒，下接缝落在基座。
