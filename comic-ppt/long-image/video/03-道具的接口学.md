# 第 03 集｜道具的接口学
## 连续动态漫画视频执行脚本

> 系列题字：**哆啦A梦讲 deepseek-harness**
> 本集副标题：**能力缝（Capability Seam）——Service Definition / Provider / Consumer**
> 建议成片：**9:16，1080×1920，24fps，05:52，32 个连续镜头**

---

## 一、本集故事设定

野比科技遭遇安全审计：所有 AI agent 的命令执行必须在周五前从本地环境迁入隔离沙箱，否则整条产品线停发。胖虎的“裸奔服务器”被点名，小夫断言大雄必须重写全部命令工具。大雄准备通宵时，哆啦A梦用“竹蜻蜓坏了只换道具，不必重做一只手”引出能力缝：稳定的 Service Definition 把 Consumer 与可替换的 Provider 隔开。二人进入可穿行的架构空间，亲眼看见 shell seam 的分层、依赖红线与 `resolve(request): Spec` 的显式默认化；最终只替换 `cordis.yml` 中一行 Provider 配置便通过审计。验收后，agent 却在重启时忘掉刚执行过的命令，引出第 04 集“记忆面包的真相”。

### 叙事与知识目标
- 零基础观众理解“工具不变、执行环境可换”的直觉。
- 研发观众掌握 Definition / Provider / Consumer 三角色、分包与依赖红线、request/spec 分离、Misconfiguration fails loud。
- 管理观众看见架构弹性如何把合规迁移从“季度重构”压缩为“一行配置”。
- 核心命题：**三个角色齐备才是一条能力缝；Consumer 与 Provider 只通过 Definition 相认。**

## 二、世界与背景设定

- **野比科技办公室**：现代开放工区，米白纸感墙面、哆啦蓝隔板、橙色任务磁贴；数字内容均为无浏览器/操作系统外框的悬浮面板。
- **全员会议室**：深蓝主屏与红色审计警示带，长桌连接开放工区；绿色“审计通过”光效将在结尾覆盖同一块主屏，形成前后呼应。
- **便利店外廊**：深夜雨后，室内暖橙、街道冷蓝；咖啡蒸汽成为进入架构空间的数据云转场。
- **能力缝架构空间**：深蓝无穷场，蓝白等距线框；Definition 是发光契约卷轴/中枢环，Provider 是可插拔道具模块，Consumer 是只向契约伸手的工具机械臂；关键路径统一用 `#FF8C42`。
- **时间连续性**：周一上午审计通知 → 当天夜晚教学和迁移 → 周五下午验收 → 验收后重启异常。倒计时、窗外光线、咖啡量和大雄疲态必须递进。

## 四、统一美术风格与色板

- **总体画风**：藤子·F·不二雄经典角色语言结合现代科技杂志 editorial illustration；粗线条角色、扁平等距架构、细腻网点纸纹。保持“精印技术杂志”质感，不做儿童绘本式软萌渲染。
- **主色**：哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`、米白纸色 `#FAF6EE`、强调橙 `#FF8C42`、正文墨黑 `#222222`。
- **终端与代码**：底色固定 `#1E1E2E`，浅色等宽字；增删行只用柔和红/绿侧条，不改变代码本身。
- **光线逻辑**：现实办公室为米白顶光加蓝色屏光；危机使用红色边缘光；架构空间用蓝白体积光；所有正确依赖和数据流以橙光点亮。
- **线条与材质**：角色外轮廓 4–6px 视觉等效粗线，背景 2–3px；信息图保持矢量锐利，景深只用于空间层次，不模糊关键文字。
- **屏幕禁则**：绝不出现浏览器地址栏、系统标题栏、红绿灯按钮或桌面窗口边框；仅使用悬浮全息板、终端卡、发光卷轴和数据流。

## 五、视频规格

- 画幅：竖屏 **9:16，1080×1920**；帧率 **24fps**；建议母版 2160×3840 后缩至交付尺寸。
- 时长：建议 **05:52**，允许按配音在 **05:35–05:59** 内微调；不得删减技术因果与第 04 集钩子。
- 安全区：字幕距底边 180px 以上；核心文字距左右边各 80px；标题距顶边 180px。
- 输出：H.264 高码率或 ProRes 母版；48kHz / 24-bit 音频；响度目标 -14 LUFS，True Peak ≤ -1 dBTP。
- 动画：角色以 2D cut-out、逐帧表情替换和局部形变结合；信息图与镜头按 24fps 平滑运动，漫画停顿可用 2 帧抽格但不得整段静止。

## 六、动态化原则

1. **连续空间，不是一格一镜**：会议室、工位、便利店和架构空间通过跟拍、遮挡、蒸汽、光流连续进入；不复刻长图分段。
2. **动作先因后果**：老师按下警报才出现审计红光；大雄看到倒计时才收拾通宵；竹蜻蜓落到契约卷轴才生成三角色；替换 Provider 后数据流才改道。
3. **信息图必须演示行为**：节点按讲解顺序点亮；箭头有粒子流向；错误直连要先尝试、撞上红线、再熄灭；镜头至少三次穿越结构。
4. **角色始终在信息空间中行动**：人物走上分层平台、触摸节点、被数据流照亮，避免“角色站着看 PPT”。
5. **每 20–30 秒一次视觉升级**：现实危机 → 道具类比 → 三角色站台 → shell 分层 → 配置替换 → seam 地图 → 验收与记忆故障。
6. **技术文字可读**：完整代码至少稳定停留 5 秒；包名逐字呈现，文字不随景深变糊；必要时使用局部放大框而不是减小字号。
7. **表演连续**：大雄右手始终拿咖啡到进入架构空间，杯中液面随移动晃动；配置修改后杯子见底；周五验收时黑眼圈减轻但仍可见。

## 九、声音设计

- **音乐主题**：现实危机用低频脉冲与拨弦；便利店类比转暖木琴；架构空间使用合成器琶音和轻木管；验收用克制主旋律；结尾以未解决三音动机钩住下集。

## 十三、技术检查单

- [ ] 能力缝完整三角色准确：Service Definition / Service Provider / Consumer。
- [ ] Service Definition 明确为 Cordis Service 类 + `ctx` 键，**不是 TypeScript interface**。
- [ ] 明确仓库规则：seam 必须三角色完整；Consumer/扩展插件依赖 Definition，永不依赖具体 Provider。
- [ ] shell Definition 准确：`dsh-shell`、`ctx.shell`、`ShellExecutor`。
- [ ] shell Providers 准确：`dsh-bash-local`、`dsh-bash-sandbox`、`dsh-pwsh-local`。
- [ ] shell Consumers 准确：`dsh-tool-bash`、`dsh-tool-pwsh`；并包含 hooks 桥接器。
- [ ] 源码位置准确显示：`packages/shell/`；延伸阅读显示 `docs/capability-seams.md`、`packages/shell/README.md`。
- [ ] `cordis.yml` 迁移前配置逐字准确：`- name: '@deepseek-ai/dsh-bash-local'`。
- [ ] `cordis.yml` 迁移后配置逐字准确：`- name: '@deepseek-ai/dsh-bash-sandbox'`。
- [ ] Provider 替换只改 `cordis.yml` 的 `- name:` 行，Consumer 无感。
- [ ] request/spec 分离准确：`const spec = shell.resolve(request)` 后 `await shell.run(spec)`。
