# 第 4 集｜记忆面包的真相（动态漫画视频脚本）
## ——SessionEvent 日志：模型可见的一切，必须可重建

> 本文件是可独立交付的动态漫画视频制作稿，不依赖其他集数或外部设定。叙事由连续动作、镜头内变化、声画因果与动态信息图推进，禁止把静态长图段落或宫格直接平移成视频。

## 一、本集故事设定
- **本集目标**：讲透 deepseek-harness（`dsh`）最深刻的设计原则——**model-visible ⟺ logged**（凡模型可见，必可从日志重建），以及 `SessionEvent` 日志、surface 投影与持久化体系。
- **研发收获**：理解 `deriveMessages()` 为什么是模型历史的唯一来源；`SessionEventMap` 如何通过 TypeScript declaration merging 扩展；`surfaceOp: append | replace` 的语义；`SESSION_FORMAT_VERSION = 0` 所表达的预发布立场。
- **领导收获**：理解 agent 每一次思考与行动都有完整审计轨迹；这不是附属日志功能，而是合规、回溯、计费、事故定责、会话恢复与迁移的基础设施。
- **前情与起因**：迁移沙箱后，大雄发现 agent 重启便“失忆”：它明明执行过命令，却说没有相关记录。大雄把历史塞进内存 `memory` 数组，短暂成功，却再次随进程重启消失。
- **核心转折**：哆啦A梦揭开“记忆面包”的真相——记忆不在任何“脑子”或内存对象中，而在一条 append-only 的事件日志里；状态和模型历史都由日志投影、重放而来。
- **结局与钩子**：会话通过日志重放完整恢复，大雄理解 Event Sourcing + CQRS；他追问事件是谁、按什么顺序写入，引出下一集 agent loop 的 `turn` / `step` / `inbox` 与工具执行管线。

## 二、世界与背景设定
故事发生在近未来的“野比科技”研发部。现实空间包括开放办公室、服务器走廊、会议白板区与夜间机房；技术概念会被具象化为可进入的“日志时间之河”“事件族谱”“surface 投影厅”和“持久化管网”。现实与概念空间必须由同一物件连续变形衔接：终端光流变成河流、事件卡变成族谱节点、投影光束变成存储管线，不能无因跳切。所有屏幕均为无操作系统边框的悬浮全息面板、深色终端卡片或数据光带。

## 四、统一美术风格与色板
- **画风**：藤子·F·不二雄经典哆啦A梦角色形象结合现代科技杂志 editorial illustration；角色用简洁粗线条，技术空间用扁平化等距线框、细腻网点和矢量光效。全彩、锐利、2K 质感，不做儿童绘本式软糯渲染。
- **主色**：哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`、米白纸感 `#FAF6EE`、强调橙 `#FF8C42`、正文墨黑 `#222222`；终端底色 `#1E1E2E`，代码为浅色等宽字。
- **情绪色**：昨天/成功用暖绿与橙光；失忆/风险用冷蓝与灰紫；原则揭示用蓝白放射光和橙色双向箭头；日志事件按 user 蓝、assistant 白、tool-result 橙区分。
- **构图纪律**：竖屏纵深优先，人物通常不超过画面高度的 1/2；用前景设备、中景人物、后景数据结构形成层次。禁止均分宫格、静态大头像、整屏文字墙、浏览器或操作系统窗口外框。

## 五、视频规格与动态化原则
- **画面规格**：9:16，1080×1920，24fps，全彩；建议成片约 5 分钟，允许配音后在 4–6 分钟内微调。
- **安全区**：字幕底线高于底部 220px；关键标题避开顶部 160px；技术代码卡完整置于中央安全区。
- **动态原则**：每镜至少包含“进入动作—动作变化—结果反馈”三段；人物呼吸、眨眼、视线、手势与衣摆必须持续微动，禁止把单张插画只做推拉。
- **连续原则**：上一镜末动作必须成为下一镜起点；视线方向、人物站位、道具手别、光源方向和事件卡流向保持一致。轴线以大雄面向 agent 面板的左右关系为主，越轴必须用移动镜头交代。
- **信息图动态化**：节点按叙事顺序逐个点亮；数据流沿路径传输并留下状态反馈；讲结构时让镜头穿越节点或管线；禁止整张架构图一次性静态出现。
- **镜头内变化**：台词说到技术关键词时，相关节点才亮起、展开或被替换；声效必须与点亮、append、replace、flush、重放动作逐帧同步。

## 七、配音与字幕规范
- **配音基调**：旁白为冷静、可信的技术纪录片口吻，语速约 210–240 中文字/分钟；剧情对白自然稍快，原则与代码段放慢 10%–15%。
- **角色声音**：哆啦A梦温暖从容，原则段坚定不喊叫；大雄前半慌张、后半逐渐清晰自信；出木杉音色平稳、咬字精确；静香温和但问题锋利；老师低沉克制；agent 使用中性合成声，不做夸张机器人腔。
- **术语读法**：`dsh` 按英文字母读；`SessionEvent`、`SessionEventMap`、`surface`、`deriveMessages`、`append`、`replace`、`checkpoint`、`flush`、`Provider`、`Projection` 保留英文读法，首次出现可在字幕用中文短注释，不改代码拼写。
- **字幕**：简体中文，底部双行，每行建议不超过 18 个汉字；技术标识与对白分层，人物对白用白字深蓝半透明底，旁白用米白字深灰底。字幕不得遮挡人物口型、手势、终端代码和关键节点。
- **代码与命令**：代码卡不作为普通字幕重复铺底；配音只概括结构，画面必须预留足够阅读时间。所有标点、大小写、路径、引号与括号按本稿逐字呈现。
- **可访问性**：关键非语言声效用简短方括号标注，例如“[服务器重启]”“[事件节点点亮]”，但同屏不超过一条。

## 八、声音设计
- **主题动机**：以“单个事件提示音→连续事件音阶→完整主题旋律”对应从失忆到可重建；结尾将主题改成未完成上行音型，引向 agent loop。
- **现实空间**：办公室保留空调、键盘、服务器风扇、纸笔等轻环境声，对白时压低 6–9dB。
- **概念空间**：日志河用细颗粒流水与数字噪声混合；append 是单次磁吸“咔”；replace 是框选滑音加磁吸双击；invariant 拒绝是低频屏障冲击；flush 是蓄能后释放；重放是节点音阶逐步恢复。
- **音乐结构**：00:00–00:41 悬疑电子；00:41–01:12 滑稽拨弦后骤停；01:12–02:30 流动弦乐与规律脉冲；02:30–02:53 原则揭示达到峰值；02:53–04:11 理性木琴/贝斯；04:11–04:43 恢复段建立并解决和声；04:43–05:00 温暖收束后留钩子。
- **混音**：对白峰值约 -6dBFS，旁白约 -8dBFS，音乐常态低于对白 10–14dB；重要系统提示音不得与技术关键词同频竞争。

## 十、动画执行说明
1. **角色表演**：每个对话镜头至少配置眨眼、呼吸、眼神转移、口型、手势收势五类微动画；同一人物相邻镜头姿势必须由上一动作自然过渡。
2. **口型**：按中文音节粗分闭口、半开、全开、圆唇四形；英文术语单独校准。旁白期间人物不做无意义口型。
3. **事件卡**：统一圆角卡片组件；事件名为等宽字。append 时从生成点进入队尾，replace 时只改变 surface 投影，底层日志卡不消失。
4. **数据流**：采用沿路径运动的粒子与亮度波峰，不用单纯箭头闪烁；流向始终从上游到下游、从写路径到存储/旁路。
5. **节点点亮**：未讲到的节点维持 35% 亮度；配音提及时升至 100%，随后回落到 65% 保持已激活状态。
6. **镜头穿越**：穿越 `request/header`、`deriveMessages()`、Projection 齿轮时使用形状匹配，进出方向一致，防止观众空间迷失。
7. **终端与代码**：全部以悬浮卡片出现，无浏览器栏、系统标题栏或红绿灯按钮；代码不做会影响准确性的字符乱序动画。
8. **粒子预算**：日志河与重放段粒子密集，但需避开字幕区与代码字形；运动模糊仅用于高速穿越，技术文字始终锐利。
9. **帧率与快门感**：24fps；常规运动按接近 180° 快门观感，重启闪白不超过 3 帧，避免频闪不适。
10. **色彩连续性**：现实办公室的窗光随时间从暖日光→冷晨光→蓝调傍晚变化；概念空间橙色只用于关键路径与风险圈，不滥用。
