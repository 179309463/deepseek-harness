## 一、本集故事设定

季度末的野比科技陷入交付地狱。产品经理静香把“重构、测试、文档”三项彼此独立、却都必须周五交付的任务同时压到大雄桌上；与此同时，胖虎的实验性清理脚本顺着软链越界，差点破坏共享服务器。吞吐不足与执行风险在同一天爆发，老师要求团队同时解决“如何分工”与“如何隔离”。哆啦A梦拿出两件架构道具：用“分身术”解释 subagent 多 Provider 委派，用“任意门”解释由 `ctx.fs` 与 `ctx.subprocess` 构成、可整体迁移到 E2B 的执行世界。最终三线任务并行完成，危险实验被限制在沙箱中；但深夜，agent 突然执行 `cordis_inspect` 检查并准备修改自身，引出第 08 集。

### 本集叙事目标
- 零基础观众能看懂：主 agent 为什么要委派、为什么不能无限递归分身、为什么高危工具必须隔离。
- 研发观众能掌握：six Providers、多 Provider 并存按名选择、capability 契约、one-shot / continuable、`maxDepth: 3`、E2B 三件套、Ralph 的 round 层策略。
- 管理观众能形成判断：委派提升吞吐与专业化，沙箱满足安全与合规，ACP 降低异构 agent 生态锁定风险；E2B 当前为 POC，应先试点验证。

## 二、世界与背景设定

- **野比科技办公室**：现代开放工区，米白纸感墙面、哆啦蓝工位隔板、橙色任务磁贴；所有数字内容均为无系统外框的悬浮全息面板。
- **共享机房**：深蓝金属机柜、青蓝状态灯、红色危险警示；事故后出现可视化软链光路与烟雾，但不表现真实灾难伤亡。
- **架构全息空间**：办公室在镜头推进时可解构为深蓝无穷空间，信息节点为蓝白等距线框，关键数据流为强调橙；人物始终保留地面或瞭望台参照。
- **本地世界与 E2B 世界**：两个可穿行的球形泡泡；本地世界偏暖白与蓝，E2B 沙箱偏深蓝与橙色边界，粉色任意门连接二者。
- **时间连续性**：周四上午接任务 → 同日下午事故 → 当晚架构教学与配置 → 周五 17:00 交付 → 当晚 23:47 自检异象。窗外天色、钟表和人物疲态随时间推进。

## 三、人物固定锚点
### 哆啦A梦
- **固定造型**：经典蓝色机器猫，白肚皮，红项圈、黄铃铛、四次元口袋；轮廓粗而干净，不改变比例与配色。
- **性格/表演**：睿智从容，面对技术危机不慌；讲解时先让观众看到因果，再给概念名称。小幅抬眉、眯眼微笑、掌心托物是固定动作。
- **声音锚点**：温暖、清晰、略带顽皮；中速，技术词放慢半拍；重要结论降低音高并留 0.3 秒停顿。

### 大雄
- **固定造型**：黄 T 恤、蓝短裤、圆眼镜，“野比科技”工牌，双肩包常挂椅背；加班后头发略乱但服装不变。
- **性格/表演**：初级程序员，容易慌张但善于追问；紧张时推眼镜、缩肩、手指悬在键盘上，理解后眼睛发亮并前倾。
- **声音锚点**：青年男声，偏高、语速随焦虑加快；提问尾音上扬，理解技术后转为笃定。

### 静香
- **固定造型**：粉色裙子，怀抱需求文档与橙色任务夹，产品经理气质。
- **性格/表演**：温和但目标明确；派任务时动作利落，交付时先确认结果再露出惊喜。
- **声音锚点**：清亮女声，中速，任务期限重读，不尖锐。

### 胖虎
- **固定造型**：橙色条纹衫，体格壮，袖口撸起，常抓着脚本卷轴或键盘。
- **性格/表演**：大力出奇迹，先做后想；闯祸后嘴硬、眼神躲闪，谈“无限分身”时又立刻兴奋。
- **声音锚点**：低沉响亮、语速偏快；事故后音量缩小，喜剧感来自反差而非吼叫。

### 老师
- **固定造型**：深色西装，部门技术总监，手持复盘夹或签字笔。
- **性格/表演**：严肃公正，只追根因不羞辱个人；思考时扶镜框，作决定时笔尖敲一下文件夹。
- **声音锚点**：沉稳男中音，短句、有停顿；结论像会议决议。

### 出木杉
- **固定造型**：白衬衫，端正沉稳，平板或白板笔在手。
- **性格/表演**：擅长把复杂架构压缩成模型；指图时动作精确，听懂他人问题后轻点头。
- **声音锚点**：清晰克制的青年男声，中低音，技术术语发音准确，像可靠的架构师。

### subagent 分身视觉规则
- 不是新增真人角色，而是大雄/agent 的半透明蓝色轮廓化身；分别携带扳手（重构）、烧瓶（测试）、卷轴（文档）。
- `spawn` 分身光面干净无历史纹理；`fork` 分身背后带父会话卷轴；外部 Provider 分身胸前显示协议徽记。
- 分身无独立配音，任务结果用提示音、字幕卡和主 agent 复述表达，避免人物声线混乱。

## 四、统一美术风格与色板

- **风格**：经典简洁粗线条机器猫漫画角色语言 + 现代科技杂志 editorial illustration；扁平等距线框、细腻网点纸纹、锐利矢量边缘。不是儿童绘本，不做写实 3D。
- **主色**：哆啦蓝 `#2B9FE3`；深蓝 `#1B5FAA`；米白纸感 `#FAF6EE`；强调橙 `#FF8C42`；正文墨黑 `#222222`。
- **代码卡**：底色 `#1E1E2E`，浅色等宽字；字符串用暖橙、注释用灰蓝、关键 API 用亮青。禁止浏览器、Windows/macOS 标题栏、地址栏或红绿灯按钮。
- **危险色**：仅用受控的珊瑚红表示越界、闸门和事故；安全边界仍以蓝色透明罩为主，避免把全片变成警报红。
- **光线**：办公室日景为米白柔光；事故为冷蓝机柜光与局部橙红闪烁；教学为深蓝空间加橙色数据流；结尾 23:47 用孤立终端蓝光。
- **构图**：人物通常占画面 1/4–1/2，保留环境、道具和数据层；不用静态宫格。需要漫画感时以斜切遮罩、速度线、破格道具作运动转场。

## 六、动态化原则

1. **动作先于解释**：先看到任务压垮大雄、脚本越界、分身接活、工具穿门，再出现概念名；每个技术结论都有剧情原因。
2. **连续动作接镜**：任务单飞出→变为委派光卡；软链红线→变为 Provider 连线；闸门线→变为沙箱边界；接力棒→变为交付勾号。
3. **镜头内必须变化**：人物至少有呼吸、视线、手势或重心变化；面板至少有数据推进、状态变化或节点反馈，禁止把长图平移当视频。
4. **信息图逐节点点亮**：六个 Provider 必须按节奏逐一出现；依赖/数据流沿线运动；镜头需至少一次穿越节点或任意门，禁止静态念图。
5. **前中后景分层**：前景用任务纸、烟、数据粒子制造视差；中景承载人物；后景承载办公室/架构。重要转场以物体擦镜完成。
6. **因果可追踪**：每次 UI 变化都由点击、拖拽、命令或数据返回触发；每个结果勾号必须能追溯到此前被委派的任务。
7. **代码原文优先**：代码出现时镜头减速并保证可读，旁白不逐字符朗读，而是解释“动作—结果”。

## 九、声音设计

- **主音乐动机**：木琴 + 轻电子脉冲代表系列感；分身段加入左右声道卡农；任意门段加入空间颗粒与低频空气感；深夜钩子只保留低音脉冲。
- **Provider 节点**：六个节点各有同音色不同音高，按点亮顺序组成完整六音动机，帮助观众听觉记忆 six Providers。
- **数据流**：移动方向必须匹配声像；橙色数据珠从上到下时，音高与声像同步下移，不使用无方向“科技嗡声”。
- **沙箱内外**：罩内爆炸与风扇声做低通和短混响，罩外保持干净，听觉上证明隔离有效。
- **任意门**：开启由机械锁扣、空气抽离、清脆铃声三层构成；跨门瞬间做 200 ms 频谱翻转感，但不影响对白清晰。
- **混音参考**：对白约 -16 LUFS 短时优先，成片综合响度建议 -14 LUFS，True Peak ≤ -1 dBTP；音乐在对白下至少让出 6 dB。

## 十一、动画执行说明

1. 角色采用 2D 骨骼 + 手绘关键表情：眨眼间隔 3–6 秒，焦虑场景可缩至 2–3 秒；口型至少区分闭口、开口、圆口、齿音四态。

3. 六 Provider 节点必须真实逐个点亮，不得一次性全亮；数据珠需穿过节点中心并触发局部反馈。
4. 委派树每生成一层，都要同时更新深度数字、token 计数和父子连线；第四层先尝试生成再被闸门拒绝，因果才成立。
5. E2B 迁移先替换地基，再驱动 Consumer 迁移；顺序固定为沙箱控制→文件系统→进程→bash/PTY/LSP 响应，不得倒放。
6. YAML 与 TypeScript 代码采用真实文本图层，禁用 AI 生成乱码；逐行高亮只改变背景或描边，不改原文。
7. 终端 `cordis_inspect` 必须表现为“无人输入却自行出现”，但不夸张成恶意入侵；橙色 `(draft)` 是下一集自修改的唯一危险提示。
8. 烟雾、数据粒子、光轨均限制在关键区域，字幕和代码上方不得有高频粒子干扰阅读。
9. 所有全息面板无浏览器/操作系统外框；仅保留内容卡、节点、数据流与必要标签。
10. 若压缩总时长，优先删减镜头落幅后的静止帧，绝不删除 six Providers、两种委派代码、`maxDepth: 3`、E2B 配置、Ralph 或结尾命令。
