# 第 01 集动态漫剧脚本｜如果 agent 是一只哆啦A梦
## 什么是 Agent Harness，为什么「一切皆插件」

> 本文件是独立、完整、可直接交给导演、分镜、原画、动效、配音、剪辑与技术校对团队执行的竖屏动态漫剧脚本。它保留第 01 集源稿的核心故事、关键对白、技术概念、准确命令、地址、包名与第 02 集钩子，但叙事、镜头组织和信息图展示均按连续运动重新设计，不采用静态长图段落或“一格一镜”的翻页方式。

## 一、本集故事设定

- **故事目标**：大雄入职野比科技第一天，被迫给三千行、牵一发而动全身的祖传单体 agent「铁雄一号」加入网页搜索能力。小夫建议换框架重写，胖虎建议把搜索代码硬塞进源码，两条路都不可行。深夜，哆啦A梦带来 DeepSeek Harness，以“四次元口袋”解释 Agent Harness 与「Everything is a Plugin（一切皆插件）」；大雄最终建立 loop / tools / session 的最小心智模型，并理解 Cordis 是只管理插件加载、卸载与依赖关系的极小内核。
- **研发观众收获**：知道 `npx @deepseek-ai/dsh web` 能启动官方 Web UI；理解 `core/agent-loop`、`core/tools`、`core/session`；理解新增能力应“写插件、挂配置”，不应硬改 loop。
- **领导观众收获**：DeepSeek Harness（`dsh`）是 DeepSeek AI 于 2026 年 8 月以 MIT 协议开源的、模型无关的 agent 基础设施；它对标 Claude Code / Codex 的底层运行时而非产品复刻，当前处于 Developer Preview，适合试点，不宜直接放入生产核心链路。
- **剧情时间**：同一工作日，从上午 08:55 入职延续到深夜 23:58；结尾进入抽象的四次元口袋空间。
- **核心因果链**：临时需求暴露单体耦合 → 两种传统解法同时失败 → 哆啦A梦先让系统跑起来 → 用“引擎与整车”澄清 harness 定位 → 用 loop / tools / session 拆解 agent → 进一步揭示三者及其零件均为插件 → Cordis 负责可组合的挂载、卸载与依赖 → 大雄从“改源码”转向“写插件挂配置” → 对口袋机制产生新疑问，引出第 02 集。

## 二、世界与背景设定

1. **现实层｜野比科技**：近未来软件公司，米白墙面、深蓝地毯、开放工位、玻璃会议室；办公设备不出现浏览器或 Windows/macOS 窗口外框，屏幕内容以悬浮全息面板、深色终端卡片与数据流光带呈现。
2. **代码层｜铁雄一号内部**：祖传单体 agent 被视觉化为灰蓝色机械巨兽，模型适配、工具注册、会话状态与主循环焊成一团；故障时橙红警示光沿耦合线路反向蔓延。
3. **讲解层｜Harness 展示舱**：哆啦A梦用 `dsh` 芯片展开蓝白等距线框空间；现实办公室仍作为半透明底层，确保讲解不是脱离剧情的 PPT。
4. **抽象层｜Cordis 四次元口袋**：深蓝漩涡与无限插槽构成的空间，插件是蓝白发光方块，关键路径为强调橙；挂载、卸载、依赖与回滚都通过可追踪的光流体现。
5. **连续性规则**：上午自然光偏暖，傍晚转冷，23:47 后以显示器蓝光和城市霓虹为主；咖啡罐从 1 个逐渐增加到 5 个；大雄的领口、头发与眼镜逐步疲惫凌乱，理解概念后姿态重新挺直。

- **老师／部门技术总监**：深色西装、白衬衫、矩形眼镜；严肃、公正、重视交付风险。前半段通过电话全息头像出现，后半段在办公室审阅技术选型报告。

## 四、统一美术风格与色板

- **总体画风**：藤子·F·不二雄经典哆啦A梦角色形象结合现代科技杂志 editorial illustration。人物用简洁粗线条与有限帧表演，环境和信息图用扁平化、等距线框、细腻网点纹理；全彩、高清、锐利、矢量感，不做儿童绘本质感。
- **统一色板**：哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`、米白纸感底 `#FAF6EE`、强调橙 `#FF8C42`、正文墨黑 `#222222`；终端卡片底色固定 `#1E1E2E`，代码用浅色等宽字。故障警示允许短暂使用橙红，但不得改变主色系统。
- **材质与光线**：现实层保留纸张网点和柔和阴影；全息信息层具有 10%–25% 透明度、细线扫描与微粒；夜景用深蓝渐变，人物肤色与服装保持本色。
- **构图约束**：角色多用全身、七分身或半身场景化表演，除关键情绪插入外不让头像占满画面；技术文字最小字号按 1080 宽画布不低于 32px；任何屏幕都不画操作系统或浏览器外框。
## 五、视频规格

- **画幅与分辨率**：竖屏 9:16，主交付 1080×1920；建议同步保留 2160×3840 母版。
- **帧率**：24fps；角色常规动作按二拍制作，镜头运动、光流、字幕和 UI 动效按一拍制作。
- **建议总时长**：05:20；容许配音后在 05:10–05:35 之间微调，但技术代码展示时长不得缩短。
- **镜头数**：30 个连续镜头，无静态分页、无“漫画格逐格推移”。
- **安全区**：核心人物眼睛、代码、字幕置于 x=90–990、y=160–1720；顶部 120px 与底部 200px 不放关键信息。
- **字幕**：中文简体，技术术语、命令、地址和包名保留原文；对白主字幕每行不超过 18 个汉字、最多两行，技术卡片不与对白字幕重叠。
- **输出**：H.264 高码率审片版、ProRes 422 HQ 中间版、分轨 WAV（对白／音乐／音效）及无字幕净画面。

## 六、动态化原则

1. **动作因果优先**：每镜起点必须接住上镜动作、视线、光线或音效，镜头结尾必须为下一镜提供明确的运动方向与视觉对象。
2. **连续空间优先**：办公室工位、走廊、老师办公室的位置固定；大雄桌面左侧是电话，中间是全息键盘，右侧是抽屉，窗户在后景。不得因镜头反打随意交换。
3. **信息图不静止陈列**：节点按讲解顺序逐一亮起；箭头先画出再流动；镜头可沿数据流推进、穿过节点进入内部；已讲节点降至 40% 亮度，当前节点保持橙色。
4. **代码逐字准确**：终端输入采用逐字打字动画，命令、地址、目录、文件名、包名不得改写；输入完成后保留足够停留时间供观众阅读。
5. **现实与抽象无缝变形**：毛线代码球可变成耦合线路，`dsh` 芯片可展开 Harness 展示舱，四次元口袋可变成 Cordis 内核；不使用硬切 PPT 页面。
6. **角色持续表演**：即使是技术讲解，角色也要有呼吸、眨眼、手部指向、重心转移和互相回应；禁止人物定格站桩。
7. **纵屏动线**：重要信息自上而下展开；向上运动表达追溯与抽象，向下运动表达执行与落地，橙色数据流统一作为认知引导线。

- **旁白**：中性青年声，清晰、克制、带技术纪录片质感；常速 210–230 字／分钟，技术定义降至 190–205 字／分钟。
- **大雄**：青年偏高声线，前半段语尾不稳、常有吸气和迟疑；镜头 26 后节奏变稳，镜头 28 的交付确认不再结巴。
- **哆啦A梦**：温暖、镇定、略带幽默；讲技术时不要变成授课腔，关键句“问题不在你的代码”前留 6 帧停顿。
- **老师**：低沉、短句、电话段有轻微带宽压缩；结尾“第一次交付，通过”要严肃中带认可，不夸张煽情。
- **小夫**：语速偏快、尾音上扬，展示 demo 时带自得笑气。
- **胖虎**：音量大、胸腔共鸣强；不可盖过关键词“直接把搜索代码塞进去”。
- **出木杉**：平稳、逻辑清楚，英文术语读音统一；解释空间／时间可组合性时每个分句间隔 4–6 帧。

### 字幕规范
1. 主字幕位于底部安全线上方，字号建议 46–52px，思源黑体 Medium，白字配 70% 深蓝半透明底或 3px 深色描边。
2. 每行最多 18 个汉字，最多两行；按语义断句，避免把 `deepseek-harness`、`Agent Harness`、`Developer Preview`、包名、命令与地址拆行。
3. 旁白字幕左对齐，对白字幕居中；说话人不明确时使用角色名色签，大雄为米白、哆啦A梦为哆啦蓝、老师为深蓝、出木杉为浅蓝。
4. 技术卡片中的代码不并入对白字幕；口播提到代码时，字幕必须逐字保持：`npx @deepseek-ai/dsh web`、`http://127.0.0.1:3080`、`cordis.yml`、`core/agent-loop`、`core/tools`、`core/session`。
5. 中文全角标点统一；代码内半角符号、斜杠、连字符、括号保持原样。技术词第一次出现时可加中文解释，之后不重复释义。
6. 字幕入点提前语音 1–2 帧、出点延后 2–3 帧；连续对白之间至少保留 1 帧间隙；终端成功信息至少完整停留 72 帧。

## 九、声音设计

- **音乐主轴**：开场轻快科技爵士代表“探索”；祖传单体段加入不稳定半音与旧机械噪声；哆啦A梦登场后主题被铃铛和合成器重新组织；技术讲解使用稳定脉冲，结尾以未解决和弦引出下一集。
- **角色动机**：大雄为木琴与单簧管；哆啦A梦为铃铛加柔和合成器；胖虎为大鼓和低音铜管；小夫为短促电子提示音；出木杉为钢片琴与均匀时钟音。
- **技术音效语义**：蓝色节点亮起用短脉冲；橙色关键路径用由低到高的扫频；挂载用实心“咔哒”；卸载与回滚用同一音色倒放；依赖未满足不得使用成功音。
- **空间声场**：现实办公室有空调、键盘、远处脚步与雨声；抽象展示舱减少环境反射，突出数据流；口袋隧道增加宽阔混响与低频，但对白响度始终优先。
- **混音建议**：对白目标约 -16 LUFS integrated，峰值不高于 -1 dBTP；音乐在对白下自动下压 4–6 dB；命令输入、成功勾与关键插拔音效可短暂前置，但不可掩盖配音。

## 十、剪辑节奏

1. **00:00–01:18｜问题建立**：平均镜头 9–11 秒，电话需求和报错处允许 4–8 帧冲击剪辑；岔路蒙太奇节奏最快，明确两种错误方案的因果。
2. **01:18–02:14｜转折与启动**：深夜段先慢后快；抽屉登场给足 12 帧光效预备；输入命令时不跳切，让观众确认完整字符。
3. **02:14–03:23｜心智模型**：镜头运动流畅，讲一个节点只高亮一个节点；Loop、Tools、Session 三段保持相似节拍但动作内容不同，避免机械重复。
4. **03:23–04:32｜理念与架构**：插件树、焊死／插拔、四层架构逐步增加信息密度；每出现一组新标签，至少给 36–48 帧无新增信息的阅读窗口。
5. **04:32–05:04｜结论与交付**：节奏重新回到现实剧情，开发笔记与领导结论分别服务不同受众；交付成功不做大段欢呼，强调方法转变。
6. **05:04–05:20｜钩子**：先用 8 秒安静提问，再用 8 秒高速穿越；最终标题至少停留 48 帧。
7. **转场限制**：优先使用动作匹配、视线匹配、光流追踪、形状变形和前景遮挡；除电话挂断与重大报错外少用硬切，不使用翻页、棋盘格或 PPT 推拉转场。

### 信息图与 UI 动画
- 所有架构图采用可编辑矢量层；节点、标签、连线、数据流、角色和背景分别分层，禁止把整张架构图做成单张静态贴图。
- 节点亮起顺序必须服从口播；亮起前为 25%–40% 亮度，当前节点橙色，讲完回落到 60% 蓝色，不突然消失。
- 数据流每秒移动 180–260px，转弯处做缓入缓出；依赖关系先绘制连线、再发送脉冲、最后允许挂载，因果顺序不可反转。
- 穿越节点时先放大边缘线框，再隐藏外壳、展示内部结构，离开时反向复原；确保观众知道镜头位于哪一层。
- 终端卡片固定深色 `#1E1E2E`，不出现浏览器地址栏、系统标题栏、红绿灯按钮或窗口边框。

### 镜头与合成
- 2.5D 场景至少拆前景、中景、后景三层，移动时保持 1:0.55:0.2 的视差参考；信息图空间可增加第四层微粒。
- 镜头缓推一般控制在画面尺度 100%→112%，高速穿越仅用于镜头 05、13、23、30；其余镜头避免无动机摇晃。
- 全息层混合模式优先 Screen／Add，但白色不得过曝；人物线稿始终保持 `#222222` 或深蓝，不被光效吞没。
- 每镜预留 8–12 帧动作柄；前后镜用同一运动矢量承接时，速度误差不超过 15%。
