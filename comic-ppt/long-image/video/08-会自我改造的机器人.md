# 第 08 集《会自我改造的机器人》连续动态漫画视频脚本
## 副标题：自修改运行时 × 上下文压缩——agent 的内省与消化

> 本文件是独立、完整、可直接进入分镜预演、配音、动画与后期制作的竖屏动态漫画脚本。它将静态长图素材彻底重构为连续时空中的故事，不采用段落翻页或宫格照搬。

## 一、本集故事设定

- **故事目标**：让零基础观众看懂 dsh 的两项高阶能力：agent 可通过 Cordis 工具集检查并临时扩展自身；长任务可通过 compaction 控制上下文压力，并在 `context-overflow` 后恢复。
- **剧情起点**：承接上一集的深夜异象。大雄回到工位，发现 agent 正在滚动检查自己的服务、工具、fiber 与动态包。
- **主要冲突**：大雄担心“会改造自己”的机器人失控；胖虎想把能力变成“无敌外挂”；老师要求说清安全边界。随后，一场持续四小时的报表任务又让上下文逼近极限。
- **行动主线**：哆啦A梦先用 `cordis_inspect / cordis_define / cordis_run / cordis_stop / cordis_undefine` 演示“检查—定义—运行—停止—遗忘”，再带众人进入 compaction 流水线，展示压力检测、无模型剪枝、LLM 摘要和 `replace` 替换。
- **结果**：临时报表美化插件在不改源码、不发版、不重启的情况下生效并被安全卸载；爆满的上下文经压缩与溢出恢复继续执行，而 append-only 日志保持完整。
- **主题**：真正高级的自修改不是没有边界，而是“能力可扩展、动作可回滚、过程可审计、失败可恢复”。
- **结尾钩子**：老师追问“怎么接进公司现有系统、值不值得全面铺开”，引出第 09 集《从玩具到生产线》。

## 二、世界与背景设定

故事发生在近未来的“野比科技”研发楼。现实层是可触摸的办公室、实验室、会议室与城市屋顶；技术概念不以浏览器或操作系统窗口出现，而会投影为悬浮终端卡片、全息器械、数据流光带和可进入的微缩信息世界。

- **深夜办公室**：23:47，绝大多数工位熄灯；窗外深蓝城市，百叶窗切出冷色条纹。大雄工位有暖黄台灯与终端蓝光，形成冷暖对撞。
- **Cordis 全息检修室**：由哆啦A梦胸前检修盖展开；中央是 agent 光核，五种工具化为环绕器械，动态插件是带插槽的发光方块。
- **边界走廊**：三道连续闸门分别象征“进程内存”“重启即失”“vm 不是安全边界”；地面红色虚线连接第 5、6 集的审批与沙箱意象。
- **下午任务区**：同一办公室自然光由金黄转橙红，墙上时钟和咖啡杯数量体现四小时流逝；上下文以贴满 tool result 的巨蛇表现。
- **Compaction 微缩车间**：垂直传送带贯通四站；信息节点按因果逐一点亮，橙色数据流只在前一站完成后进入下一站，镜头必须穿越节点而非静态念图。
- **产品化大桥**：结尾的屋顶与城市天际线之间出现 ACP / SDK / Python 三条发光车道，桥墩刻“工程纪律”，连接下一集。

## 四、统一美术风格与色板

- **视觉总风格**：藤子·F·不二雄经典哆啦A梦角色形象 × 现代科技杂志 editorial illustration。角色用简洁粗线条与有限帧表演，背景和信息图使用扁平化等距线框、细网点纸纹和锐利矢量边缘；是“印刷精美的技术杂志动起来”，不是儿童绘本，也不做写实 3D。
- **主色**：哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`。
- **底色**：米白纸感 `#FAF6EE`；正文墨黑 `#222222`。
- **强调色**：橙 `#FF8C42`，仅用于关键路径、当前激活节点与结论。
- **终端卡片**：底色 `#1E1E2E`，浅色等宽字，蓝色命令、橙色参数、绿色成功态、红色错误态。
- **危险态**：`context-overflow` 与非安全边界使用暗红 `#D94B4B`；红色只在警报阶段出现，恢复后回落到蓝橙体系。
- **光线逻辑**：深夜为窗外深蓝 + 台灯暖黄；检修室为蓝色体积光 + 橙色关键插槽；下午先自然暖光、压力升高后逐渐加入红色顶光；结尾回到深蓝城市与橙色桥灯。
- **屏幕规则**：禁止浏览器地址栏、系统标题栏、红绿灯按钮和操作系统边框；所有界面均为融入场景的悬浮卡片、卷轴、投影或数据流。

## 五、视频规格与建议总时长

- **画幅**：9:16 竖屏，1080 × 1920；重要人物、代码与字幕位于中央 900 × 1550 安全区。
- **帧率**：24fps；快动作可按 12fps 角色有限帧 + 24fps 镜头/粒子合成。
- **建议总时长**：**5 分 40 秒（340 秒）**，共 30 个连续镜头；允许成片在 5:30–5:50 内因配音呼吸微调，但代码阅读镜头不得被压短。
- **音频**：48kHz / 24bit；对白目标响度 -16 LUFS（短视频平台可整体归一到 -14 LUFS），真峰值不高于 -1dBTP。
- **输出**：H.264 高码率审片版 + ProRes 422 母版；字幕另交 SRT/ASS，并保留无字幕 clean feed。
- **安全区**：顶部 160px 避开平台标题，底部 260px 避开操作栏；技术卡片字号不小于 42px，主标题 100–120px，字幕 48–56px。

## 六、动态化原则

1. **连续时空，不翻静态页**：每镜结尾必须留下动作、视线、声音或运动方向，下一镜从同一线索接续；不得用“下一段信息图”式硬切。
2. **角色动作有准备—发生—余波**：例如大雄先听到终端滚动声，再探头，再僵住；按钮先被手指接近，再按下，再产生数据响应。
3. **技术信息必须发生**：节点按顺序点亮，箭头中有数据包运动；镜头可跟随数据包穿越 inspect、define、run、stop、undefine 或 compaction 四站，禁止对着一张静态架构图念旁白。
4. **代码逐字准确**：代码/命令给足停留时间，不做透视变形；关键行用光标、下划线或局部放大引导，禁止改写源码字符。
5. **镜头内持续变化**：每个镜头至少包含两项变化，如角色位移 + 灯光变化、节点激活 + 数据流推进、表情变化 + 道具反馈。
6. **层级视差**：前景用电缆、桌沿、飞过的日志卡片；中景放人物与主要动作；后景放办公室/城市/架构层。横移时三层速度约 1.0 / 0.6 / 0.25。
7. **有限帧但不僵硬**：角色口型 6–8 个基础形，眨眼、呼吸、手指和耳朵/铃铛微动独立成层；信息图、数据流与光效保持 24fps。
8. **转场服务因果**：终端光标变成检修室光线；插件方块旋转匹配切到记忆面包方块；红色 overflow 墙的裂纹转为产品化大桥路网。

- 主字幕：思源黑体 Heavy / 等宽技术词混排；字号 52px，行高 1.25，最多两行，每行建议不超过 17 个全角字符。

- **音乐主题 A｜自检**：低频合成器 + 木琴点音，体现“机器醒着但非恐怖”；镜头 01–05 使用。
