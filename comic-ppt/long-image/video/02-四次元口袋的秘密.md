# 第 02 集｜四次元口袋的秘密（动态漫剧执行脚本）
## Cordis 内核：Context、inject、类型化事件与可逆副作用

> 本文件是可独立制作的竖屏动态漫剧脚本。它保留原故事、关键对白、技术概念、代码与第 03 集钩子，但以连续动作、因果承接、运镜、动画层级和声音叙事重新组织；不得按静态长图逐格平移或把信息图定帧朗读。

## 一、本集故事设定

- **故事目标**：承接上一集。大雄追问四次元口袋为何能装下无数道具、用完还能完整收回。哆啦A梦将两人带入口袋内部的 Cordis 道具仓库，通过大雄“周末测试服务未关闭”的事故，解释 Plugin、Context、inject、Events、effect 五个核心概念。
- **戏剧主线**：好奇提问 → 周末事故回忆 → 进入口袋仓库 → 逐层理解依赖和生命周期 → 亲手完成一次热拔插 → 分清“插件清单”与“插件系统” → 发现接口契约的新问题。
- **研发收获**：理解 `ctx.effect()` 的可逆语义为何是热挂载、热卸载与自动回滚的地基；理解 `emit` / `waterfall` / `parallel` / `serial` 四种事件分发模式；理解 TypeScript declaration merging 如何扩展 `SessionEventMap`。
- **领导收获**：插件化不是“能加载几个插件”的口号，而是动态装卸不重启、依赖关系自动化、卸载不留残留的生命周期机制，直接影响运维成本、稳定性和长期演进。
- **技术事实**：Cordis 是 dsh 的 vendored 框架层，源码内置、可审计、版本锁定，参见 `vendor/README.md`；五概念参见 `docs/cordis-primer.md`；时空可组合性来自 Cordis 论文主张。
- **结尾钩子**：大雄问“道具换来换去，为什么你自己从来不用改？”哆啦A梦回答“因为道具和我之间，隔着一份接口契约。”引出第 03 集 Definition / Provider / Consumer。

## 二、世界与背景设定

1. **野比科技深夜办公室**：开放式工位、低矮隔断、米白墙面与深蓝夜窗；屏幕内容只能表现为悬浮全息面板、终端卡片或数据光带，不出现浏览器地址栏、操作系统标题栏及窗口红绿灯。
2. **周末事故回忆空间**：现实办公室与机房以一条向下坠落的橙红时间光轨相连，时间不是静态卡片，而是可追踪的发光节点；内存曲线、监听器、定时器和连接随事故发展实时增长。
3. **四次元口袋入口**：口袋被翻开后形成柔软的椭圆传送门，内部是深蓝到哆啦蓝的空间隧道；插件方块、标签和光线从远处掠过，建立真实纵深。
4. **Cordis 道具仓库**：纵向无限延伸的等距科技仓库。高耸货架对应 Context，挂钩上的发光道具对应 Plugin，标签光线对应 inject，传送带对应 Events，底部出入库台对应 effect。仓库会响应讲解：节点点亮、依赖光流、路径重排、登记与回滚均实时发生。
5. **事件实验厅**：同一大厅可变形成广播穹顶、流水线、并行工坊和串行议事亭；空间变形连续完成，避免四张静态定义图。
6. **插件树手术台**：透明立体插件树悬浮旋转，运行光流持续穿过所有已激活节点；拔出与插入节点时，旧贡献逆向熄灭，新贡献顺向点亮，主循环始终不断。

## 四、统一美术风格与色板

- **画风**：藤子·F·不二雄经典角色语言与现代科技杂志 editorial illustration 融合；角色采用简洁粗线条、有限帧表演，背景与信息图采用扁平矢量、等距线框、细网点印刷纹理。整体精致、清晰、有技术感，不做儿童绘本式软萌渲染。
- **色板**：哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`、米白纸感 `#FAF6EE`、强调橙 `#FF8C42`、正文墨黑 `#222222`；终端卡片固定为 `#1E1E2E`，代码为浅色等宽字并保留语法高亮。
- **信息图规则**：基础节点蓝白线框，待机时 35% 亮度，就绪时由边缘到中心点亮；依赖路径用橙色光流沿箭头行进；失败或泄漏使用克制的红色。所有图必须经历“出现—变化—得到结果”，不可作为静止背景。
- **构图规则**：竖屏优先纵深与上下运动；人物通常不超过画面高度的 1/2；重要道具允许越过漫画式斜切遮罩，但视频中遮罩须随镜头运动产生视差。

## 五、视频规格

- **画幅**：9:16，1080 × 1920；关键图形按 2160 × 3840 设计后缩放，方便推进与穿越。
- **帧率**：24fps；角色有限动画主要 12fps on twos，镜头、光效、字幕和信息图保持 24fps。
- **建议时长**：05:30；共 30 个连续镜头。
- **交付**：H.264 高码率母版 + ProRes 422 中间母版；立体声 48kHz / 24bit；另交无字幕 clean feed、对白/音乐/音效分轨和 SRT。
- **安全区**：对白字幕距底边至少 180px，左右各留 72px；技术代码与关键信息距边缘至少 96px。

## 六、动态化原则

1. 每个概念都由角色动作触发：触碰、插入、拔出、递交、按住或拼合后，图形才变化；旁白只总结已经发生的视觉因果。
2. 仓库、依赖、事件、插件树均必须使用节点点亮、光流传递、镜头穿越、路径重排与数值实时变化，严禁把静态架构图放大缩小后念文字。
3. 动作跨镜连续：上一镜抬手，下一镜从匹配方向接住；上一镜光流出画，下一镜光流从相同屏幕方位入画；角色站位、持物手和视线轴保持一致。
4. 技术内容以“问题—操作—系统反应—结论”四拍呈现；代码出现时先由动作召出，再高亮当前行，随后立即看到运行结果。
5. 漫画感来自速度线、拟声字、斜切遮罩、网点和关键姿势，不来自静止画格；单一构图无变化不得持续超过 4 秒。
6. 每次空间切换保留一个视觉桥：铃铛圆形、口袋椭圆、橙色光点或文件光带，以匹配剪辑保证连续性。

## 十一、动画执行说明

- **角色动画**：基础表演采用关键姿势 + 眼神 + 口型 + 手部精细动画。眨眼间隔 3–6 秒随机化；说话者至少有肩颈和重心变化，非说话者要有聆听反应，禁止全员木偶静止。
- **口型**：中文对白至少使用闭口、半开、全开、圆唇四类口型；技术英文词单独标注口型节奏。情绪停顿时先停口型，再做眼神或呼吸动作。
- **信息图动画**：每个节点具备 `idle / waiting / ready / active / disposed / error` 六种视觉状态；依赖光流必须从源节点沿路径到目标节点，不能整条线同时闪亮。
- **镜头穿越**：仓库和插件树使用分层 2.5D 或简化 3D；至少准备前景粒子、主体节点、后景货架三层，并添加 3%–8% 景深差。穿越节点时用真实遮挡，不只做整体缩放。
- **代码动画**：代码卡不可逐字打错后修正；按完整准确文本预排版，再用遮罩模拟写入。当前讲解行使用橙色侧边标和轻亮底，不改变任何代码字符。
- **effect 回滚**：所有撤销动画严格反向追踪注册顺序，计数最终归零；被卸载节点不得留下半透明残影、仍闪烁监听器或未断开的连接。
- **热更新**：主循环光环、心跳和性能曲线使用独立持续层，跨镜 26–28 相位连续；旧节点回滚结束后新节点才能顺向登记，但系统主循环始终保持运行。
