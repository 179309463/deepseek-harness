# 第 5 集｜一次任务的奇妙旅程（动态漫画视频脚本）
## ——agent loop：turn / step / inbox 与工具执行管线

> 本文件是可独立交付给导演、分镜、动画、配音、剪辑与技术校对团队的完整制作稿。它不是静态长图段落或宫格转场，而是一条连续发生、动作互相触发、信息随剧情逐层显影的动态漫画视频。

## 一、本集故事设定
- **核心任务**：静香向大雄的 agent 下达真实需求：“把昨天的实验数据整理成报表，周五前发我。”任务涉及读取 `lab/`、参考上周格式、运行脚本、写报表与发送结果。
- **戏剧主线**：大雄不知道 agent 会先做什么。哆啦A梦给他戴上“循环透视镜”，二人被缩入任务内部，沿一条发光流水线亲历一次完整 turn。途中胖虎试图插入危险命令，被 `tools/pre-execute` 审批闸门拦下；任务最终可审计地完成。
- **知识目标**：完整讲清 `ReactLoopAgent` 的 turn / step / inbox、`followup` / `steer` / `inject`、完整事件序列、waterfall 的 `next()` 委托语义、审批 seam、工具执行五段管线、exclusive barrier / parallel pool、请求三方来源，以及“Plugins, not loop changes”。
- **研发收获**：能够按事件顺序追踪一次任务，知道策略应挂在哪些扩展点，并理解结果为何可恢复、可拦截、可审计。
- **管理收获**：agent 的自动化不是黑箱；每一步有事件留痕，危险动作有人类闸门，机制与合规策略可独立演进。
- **结尾钩子**：大雄追问不同任务是否每次都要重搭流水线，哆啦A梦打开挂着 web、headless、CI 制服的衣柜，引出下一集 profile / preset / permission。

## 二、世界与背景设定
- **现实层**：近未来“野比科技”开放式研发办公室。白天米白暖光、蓝色玻璃反射；任务启动后转为傍晚蓝紫色。工位不出现浏览器或操作系统窗口框，所有数字内容均为悬浮面板、终端卡片、数据光带。
- **循环内部层**：透视镜把 agent 内部具象成一座纵深巨大的“事件流水线工厂”。一条橙色关键路径贯穿蓝白机械空间，事件节点会按因果依次点亮；未到达节点保持低亮，禁止一次性展示静态总图。
- **日志层**：所有事件化作带时间戳的发光票据，先后落入下方“时间之河”；历史不是临时数组，而是可投影、可回放的日志。
- **审批层**：`tools/pre-execute` 是横跨轨道的蓝色光幕闸门；`allow` 为绿灯直行，`deny` 为红灯退回，`ask` 为橙灯升起人工审批台。
- **空间连续性**：现实办公室的桌沿变形为流水线起点；流水线末端再折回静香工位。全片以同一橙色事件光点作为视觉接力物，确保观众理解始终是“同一个任务”。

- **大雄**：黄 T 恤、蓝短裤、圆眼镜，胸前“野比科技”初级程序员工牌；戴透视镜后镜片会映出事件代码。好奇、容易慌，但会主动追问因果并做笔记；动作从手抖、踉跄逐渐变为能预判节点。
- **静香**：粉色裙子，产品经理气质，手持需求便签与参考报表；表达清楚、温和但重视截止时间。她始终代表真实业务目标，不沦为纯讲解角色。
- **胖虎**：橙色条纹衫，体格壮，撸袖子；“大力出奇迹”，自信地把危险命令当清理磁盘，受阻后跳脚但不突破安全边界。
- **出木杉**：白衬衫，端正沉稳，手持平板与指示笔；作为架构观察员在关键技术处出现，语言精确，负责把现象归纳为契约。
- **老师／技术总监**：深色西装，严肃公正；仅在收束镜头审核评估报告，代表管理与合规视角，不参与流水线冒险。

## 四、统一美术风格与色板
- **画风**：藤子·F·不二雄经典角色形象结合现代科技杂志 editorial illustration；人物粗线条、简洁表情，机械空间采用扁平等距线框、细腻网点与有限景深。全彩、锐利、矢量感，避免儿童绘本质感。
- **主色**：哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`、米白纸感 `#FAF6EE`、强调橙 `#FF8C42`、正文墨黑 `#222222`；终端卡片固定 `#1E1E2E`，浅色等宽字。
- **动态色彩语义**：未触发节点为低饱和蓝灰；当前事件为橙；正常放行为绿；危险拒绝为红；人工询问为橙黄。日志票据使用白蓝微光，保证长链条中状态可读。
- **文字视觉**：中文为主，技术术语保留英文；代码、事件名、路径与命令使用等宽字体。任何屏幕内容禁止浏览器地址栏、系统标题栏、红绿灯按钮或窗口外框。
## 五、视频规格与动态化原则
- **画幅与帧率**：9:16，1080×1920，24fps；建议成片 5分30秒，允许配音落点微调 ±5 秒。
- **安全区**：核心字幕、代码与标签位于左右各 72px、顶部 120px、底部 180px 内；背景、轨道与光效可出血。
- **动态漫画方式**：角色采用 2.5D 分层、关键姿势插值、口型 6–8 个基础嘴型、眨眼与呼吸循环；禁止“静帧停十秒”。每镜至少同时发生两项变化，例如人物动作 + 节点点亮、镜头推进 + 数据流移动、表情变化 + 前景遮挡。
- **连续性原则**：前镜动作必须在后镜被接住；视线方向、手中道具、橙色任务票据的位置与流向保持一致。动作切点优先采用 match cut、遮挡切、甩镜或光点穿镜，不使用静态翻页。
- **信息图动态化**：定义、时序与架构均先隐藏，随讲解逐节点点亮；数据票据沿箭头真实移动、穿过闸门、落入日志；展示 turn 全链路时让摄影机与任务票据共同穿越结构，而不是定机拍完整图。
- **运动强度**：剧情镜头自然、可读；进入循环后运动加强；waterfall 与危险命令段节奏最快；收束段放缓。镜头运动避免眩晕，代码出现时保持至少 3 秒稳定阅读窗口。

## 八、声音设计
- **主题动机**：机械木琴 + 轻电子脉冲，代表“任务光点”；每次事件成功落日志，都以同一水滴音变调出现。
- **现实办公室**：空调、远处键盘、纸张与椅轮声，保持低电平；进入循环后逐步滤掉现实底噪。
- **流水线工厂**：伺服电机、磁吸、数据掠空与远距空间混响；不同节点有固定识别音，形成听觉上的事件序列。
- **waterfall**：`next()` 使用清脆接棒声；short-circuit 使用急刹与瞬时静音，突出“不委托”的后果。
- **审批**：allow/deny/ask 分别为绿灯短音、红灯低音、橙色双音；`approval/asked` 与 `approval/decided` 必须成对出现。
- **并发**：parallel 以多声部同时运行，结果归队时合为单声部；exclusive 屏障落下时压低其他声部，听觉上体现独占。
- **混音**：对白峰值优先，音乐在人声下压 4–6dB；技术代码镜头减少音乐细节。最终网络视频建议综合响度约 -14 LUFS，True Peak 不高于 -1 dBTP。

## 十、动画执行说明
1. **分层建议**：每镜至少拆分前景遮挡、中景角色、主任务票据、信息节点、后景工厂、光效六层；长穿越镜头增加轨道近中远三层制造视差。
2. **角色表演**：大雄眼镜反光不可始终遮眼；关键反应前后保留 4–8 帧预备与缓冲。哆啦A梦动作重心稳，胖虎冲刺重心前倾，静香翻报表动作细致。
3. **任务票据连续性**：同一主任务始终是橙芯、蓝白边框、右上角便签折角；危险命令是红芯方块，严禁混色。上一镜退出位置必须匹配下一镜进入位置。
4. **节点规则**：未触发 25% 亮度，当前 100% 橙亮，已通过 55% 蓝白余辉；不得让未来节点提前全亮。事件写日志时复制票据而非搬走原意图，体现持久记录。
5. **信息图动作**：同心环要旋转、队列要推进、waterfall 要物理交棒、并发车要真实等待归序、三方请求要汇流封包；禁止仅对静态图做缩放。
6. **代码画面**：代码逐行显现后整体稳定，不做字符漂移、伪 3D 透视或自动纠错；镜头 14、21 的文本以源稿为唯一字形内容。
7. **摄影机**：纵向穿越以缓入缓出曲线为主；快速甩镜控制在 6–10 帧并由同方向运动承接，避免 9:16 画幅眩晕。
8. **光效**：橙色只高亮当前关键路径，不全屏泛橙；审批红光只影响胖虎与危险方块，不污染安全任务轨。
9. **漫画质感**：保留速度线、网点、少量拟声字，但拟声字必须随声源出现和消失；人物轮廓不因景深模糊而断线。
10. **禁止项**：禁止静态宫格、静止头像说话、浏览器/系统窗口外框、大面积空背景、无因果炫技转场、代码拼写变化、工具结果按完成顺序错误回填。

## 十二、技术检查单
- [ ] 主循环实现：`ReactLoopAgent`，路径 `packages/core/agent-loop/src/agent.ts`；工具调度在 `tool-calls.ts`。
- [ ] turn = 一次可取消工作单元；step = 一次模型请求 + 其全部工具调用；inbox 两队列为 `next-turn` / `next-step`。
- [ ] 输入方式：`followup` / `steer` / `inject` 写入 inbox；参考 `packages/core/agent/src/inbox.ts`。
- [ ] 事件序列无缺漏且顺序正确：turn/start → claim + assemble → `agent/pre-step`(waterfall) → step/start + user/message → deriveMessages → `agent/request` → `llm/stream` → assistant/* → tool/call → tools/pre-execute → execute → post-execute → tool/result → step/end → `agent/turn-stopping`(serial) → turn/end。
- [ ] `agent/pre-step`、`agent/request`、`tools/pre|execute|post-execute` 为 waterfall；监听器必须调用 `next()`，否则 short-circuit。
- [ ] 审批决策：`PreToolDecision = allow | deny | ask`；ask → `ctx.approval.request(...)`；`approval/asked` + `approval/decided` 成对落日志。

- [ ] `executeToolCalls` 按 `executionMode` 分 exclusive barrier / parallel pool；结果按模型给出的顺序提交。
- [ ] 请求来源准确：`this.session.deriveMessages()` 历史投影 + `ctx.systemPrompt` 组装 + `request/header` 的 system / tools / config 快照。
