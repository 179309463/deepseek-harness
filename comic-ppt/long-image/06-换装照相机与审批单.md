# 第 6 集 ｜ 换装照相机与审批单（手机长图漫画版）
## ——profile / bundle / patch 组合艺术与权限审批体系

> 使用方式：将本文件**整篇**粘贴给 AnyGen，即可生成本集手机长图漫画。工具须按【逐段脚本】逐段生成 1080px 宽的竖版图片（本集共 12 段），再按【合并与产出规范】垂直无缝拼接为一张长图。全局风格设定已包含在内，无需补充其他提示词。

## 【全局风格设定 · 每集通用，务必严格遵守】

### 成品形态与生成流程
- 最终成品是**一张手机长图漫画**：宽度恒为 **1080px**，垂直向下滚动阅读，**全彩**，高清。
- 不要尝试一次生成整张长图。必须按【逐段脚本】拆成多段分别生成：每段是一张 1080px 宽、高度 1440–2160px 的竖版图片（按内容多少定高，高清渲染）。
- 全部段落生成后，按段序**垂直无缝拼接**为一张完整长图。拼接处不得出现白缝、错位或重复内容。

### 顶部与底部安全区（仅首尾两段）
- 仅在整张长图的**最顶部**留出 ≥200px、**最底部**留出 ≥200px 的安全高度：两处为背景/场景的纯净延展（不是白色边、不放任何人物、文字、道具），用于躲避手机状态栏、刘海屏、标题栏与底部手势区的遮挡。
- 除首尾两段外，其余各段上下边缘**满幅出血**，段与段之间不留任何空隙。
- 每段的上下接缝必须落在斜切格线、场景色块或天空/夜色上，**禁止接缝切过人脸、对话气泡或文字**。

### 画风
藤子·F·不二雄经典哆啦A梦角色形象 + 现代科技杂志编辑插画（editorial illustration）质感。角色为简洁粗线条漫画风，背景与信息图采用扁平化、等距线框、细腻网点纹理。整体是「印刷精美的技术杂志」，不是儿童绘本。全彩画面，高清、锐利、矢量感，2K 分辨率质感，禁止黑白稿与低分辨率感。

### 统一色板
主色哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`；底色米白纸感 `#FAF6EE`；强调橙 `#FF8C42`；正文墨黑 `#222222`。架构图使用蓝白线框 + 橙色高亮关键路径；代码一律深色终端卡片（`#1E1E2E` 底、浅色等宽字）。夜景与情绪场景可用深蓝渐变，但每段都必须保持彩色。

### 角色锚点（每集造型必须一致）
- 哆啦A梦：蓝色机器猫，白肚皮，红项圈黄铃铛，四次元口袋，表情睿智从容
- 大雄：黄 T 恤、蓝短裤、圆眼镜，初级程序员，工牌写着「野比科技」，常背双肩包
- 出木杉：白衬衫，端正沉稳，手持平板或指向架构图
- 小夫：绿色上衣、尖嘴，爱炫耀，常拿手机秀自己的项目
- 胖虎：橙色条纹衫，体格壮，撸袖子，「大力出奇迹」做派
- 静香：粉色裙子，产品经理气质，拿需求文档
- 老师：深色西装，严肃但公正，部门技术总监

### 动态分镜规则（长图的灵魂）
1. **禁止横平竖直的均分宫格**。每段 3–5 格，格子大小错落，主格占该段画面的 40–60%。
2. 格线必须动起来：斜切面板、锯齿/闪电形分割线、弧形格、梯形格交替使用；允许「破格」——角色、道具或光效探出格线 10–20%，制造冲击力。
3. 阅读动线永远自上而下：用斜切格线的指向、虚线动线、角色视线与色块流向，把视线从每段顶部引到底部，再自然滚入下一段。
4. 版式库（每段从中组合选择，禁止连续两段使用同一版式）：斜切双格、上大下小锯齿分割、出血大图 + 浮动旁白框、左窄右宽梯形双格、纵向时间轴三格、中心辐射、Z 字动线三格、满宽全景格。
5. **画面必须充实**：每一格都要有具体场景环境（办公室、会议室、深夜街道、全息空间……）、角色动作或信息图，禁止大面积空白背景，禁止「一格一个人头 + 一句话」的敷衍构图。
6. 角色在单格内不超过画面 1/2，以全身/半身的场景化姿态出现（坐着敲代码、站在白板前、围着工位）；禁止大头像特写撑满整格。
7. 每段保留一个「视觉钩子」：一道斜切色块、一个出血的道具、一条贯穿的虚线动线、一片发光特效。

### 文字规则（手机阅读的生命线）
1. 全部使用中文，技术术语保留英文原词（如 plugin、loop、session）。
2. 字号按 1080px 宽画面计，必须大且清晰：封面主标题 96–120px；剧情小节题字 64–80px；旁白框与正文 40–48px；对话气泡 40–44px；最小的图注标注也不得小于 32px。
3. 对话气泡每句不超过 20 字，但每格可以放 2–4 个气泡形成对话回合，让故事娓娓道来。
4. 旁白一律用漫画式色块旁白框（米白底或深蓝底白字），贴在格子的上缘或下缘；禁止整段文字墙，禁止一段全是字没有画面。
5. **禁止出现任何页码与编号文字**：不写「第 X 页」「第 X 段」「第 X 格」，不写 01、02 之类的序号。剧情衔接用手写感题字（如「当天深夜」「周五下午」）或纯场景过场格。
6. 架构图采用等距线框风格，节点用圆角矩形/圆柱体，箭头标注数据流，关键路径橙色高亮；架构图必须**纵向分层**（自上而下），角色站在图旁的瞭望台或地面上仰望、指点。
7. 代码/伪代码用深色终端卡片，带行号和语法高亮，卡片一角可有迷你角色注释气泡；卡片上的代码必须与脚本所写**逐字一致**。

### 屏幕呈现规则
- **禁止出现浏览器或 Windows/macOS 窗口外框**：不要地址栏、标题栏、红绿灯按钮、窗口边框。
- 所有屏幕内容一律以悬浮全息面板、深色终端卡片、发光卷轴、数据流光带的形式融入漫画场景。

### 完整结构（必须有头有尾）
- **第 1 段 = 封面（顶部标题区域）**：系列题字「哆啦A梦讲 deepseek-harness」+ 本集主标题 + 副标题 + 主视觉画面 + 顶部安全区。
- **中间各段 = 正文**：连续剧情，一气呵成，不分页、无页码。
- **最后 1 段 = 结尾页（尾部结束区域）**：本集收束画面 + 「本集完」题字 + 下集预告 + 底部安全区。

### 禁止事项
- 禁止角色占满画面、大头像特写、低分辨率感
- 禁止整段纯文字或整段纯插图
- 禁止无剧情动机的生硬说教
- 禁止四宫格式平均切分、横平竖直的宫格
- 禁止页码、段号、格号等编号文字
- 禁止浏览器/操作系统窗口外框
- 禁止大面积空白、稀疏敷衍的画面
- 禁止任何小于 32px 的文字
- 禁止黑白稿，必须全彩

## 【本集设定】

- **本集目标**：讲清 dsh 的配置组合体系（profile / bundle / patch 四层叠加）与 per-session 的 preset 机制，以及权限预设与审批策略如何构成企业级治理面。
- **研发收获**：理解启动时插件树如何按层叠加；`dsh-base` / `dsh-web-app` / `dsh-headless` 的分工；preset 在 agent 创建时挂载的隔离语义；`!!js` 表达式与 overlay 的使用边界。
- **领导收获**：同一套内核如何通过「换装」产出面向人类工作台、CI 自动化、IDE 集成的不同产品形态；权限与审批的 fail-closed 设计如何让「默认安全」成为出厂配置。本集老师戏份最重。
- **故事梗概**：公司要同时上线三种用法：研发日常用的 Web 工作台、CI 流水线上的 headless 质检 agent、以及给外包团队用的「受限版」。大雄以为要维护三套代码，哆啦A梦拿出「换装照相机」——同一个内核，换三套装备。胖虎试图给自己申请 `danger-full-access` 权限，被老师的审批单体系当场打回。
- **出场角色**：大雄、哆啦A梦、老师、胖虎、出木杉、静香
- **结尾钩子**：大雄遇到新麻烦：一个任务太大，一个 agent 干不完，能不能「摇人」？→ 引出下集 subagent 与沙箱。

### 第 1 段 ｜ 封面：换装照相机与审批单

- **画面**：顶部 200px 是渐变的深夜蓝夜空（纯净无物）。其下进入场景：一台巨大的复古照相机（换装照相机）发出扇形光束，光束中三套制服剪影依次显现（西装、工装、夜行衣）；哆啦A梦举着照相机对准大雄，大雄身上光影变换（T 恤 → 西装 → 工装）；左下角老师手持一沓审批单，表情严肃，审批单上的红章发光。

  - 标题区（夜空与主视觉之间）：系列题字「哆啦A梦讲 deepseek-harness」（48px，手写感）；主标题「换装照相机与审批单」（约 110px，深蓝粗体白描边）；副标题「profile / bundle / patch / preset——同一内核的千种形态与它的缰绳」（44px）；角标小字「第 6 集 · 组合与治理篇」（36px）。
  - 旁白框（画面下缘，深蓝底白字）：身体只有一个，衣服随便换——但换衣服也要走审批。

### 第 3 段 ｜ 概念：启动时发生了什么 —— 四层叠加
- **画布**：1080 × 2160px。上下缘满幅出血；上接缝落在钻井机光效，下接缝落在岩层核心。
- **版式**：满宽纵向「地质剖面图」（占 80%）+ 底部对话小格——四层岩层自上而下叠加，一台「加载器」钻井机从顶层钻到核心。
- **画面**：
  - 格 1（主格）：题字「插件树不是写死的，是叠出来的」。纵向等距线框地质剖面，自上而下四层——第 4 层：命令行 `--patch` 覆盖层；第 3 层：用户级 `~/.dsh/cordis.patch.yml`；第 2 层：profile 自己的 `cordis.patch.yml`；第 1 层（最底层）：profile 列出的 bundles（有序），如 `dsh-base` → `dsh-web-app`。一台发光钻井机正从顶层钻向核心。大雄站在剖面旁的小梯子上一层层看。图注：启动从**空列表**开始，四层依次叠加；patch 按插件 entry 的 `id` 整段替换配置，或插入新行；想看实际跑的树：`dsh --profile web --dump-config`。
  - 格 2（底部对话格）：气泡（大雄）：「所以『默认配置』其实也不存在？都是叠出来的？」
- **技术点**：叠加顺序：profile bundles → profile patch → home patch → `--patch`；`dsh-base` 是每个 profile 的第一层（模型适配、工具、持久化、沙箱与审批策略、设置、凭据、遥测）。

### 第 4 段 ｜ 概念：组合艺术的三种材料
- **画布**：1080 × 1680px。上下缘满幅出血；上接缝落在发光文档，下接缝落在图鉴卡。
- **版式**：中心辐射——中央 `cordis.yml` 发光文档，向下辐射三张道具图鉴卡。
- **画面**：
  - 格 1（主格）：题字「组合艺术的三种材料」。中央一份发光的 `cordis.yml` 文档悬浮，三条引线连向下方三张图鉴卡。哆啦A梦把三张卡别在口袋上。
  - 格 2（三张图鉴卡，错落排列）：**Profile 是「衣柜」**——具名组合（`web` / `headless` 是官方模板），列出自己叠放的 bundle；**Bundle 是「可快递的装备包」**——npm 包，带 `dsh.bundle` 标记，代码 + 配置行，安装即用；**Patch 是「修改贴纸」**——按 `id` 精确覆盖既有配置，支持 `!!js` 表达式做条件逻辑。
  - 格 3（边界提示格）：气泡（出木杉，画外音）：「注意边界——`!!js` 只允许出现在插件 config 和 `disabled` 字段，其他元数据必须保持字面值。」
- **技术点**：`!!js`（注意不是 `!js`）的合法位置由 loader 规则限定；条件组合也可以用 overlay 达成（`docs/cordis-primer.md`）。

### 第 5 段 ｜ 深度：preset —— 给单个 agent 换装
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在装备间灯光，下接缝落在配置卡。
- **版式**：上大下小锯齿分割——上部「特工装备间」等距图主格，下部配置卡 + 要点格。
- **画面**：
  - 格 1（装备间主格）：题字「profile 管进程，preset 管单个 agent」。等距线框「特工装备间」：不同的 agent 小人排队领取各自的任务装备包——「代码审查员」「数据分析师」「只读顾问」；每个装备柜都有隔离玻璃罩（isolate realm 的视觉隐喻），玻璃罩发淡蓝光。
  - 格 2（配置卡片）：
    ```yaml
    # presets/reviewer/cordis.yml（节选）
    - name: reviewer-tools
    - name: reviewer-persona
    ```
  - 格 3（要点 + 对话格）：要点——preset = 每个 agent 会话自己的 `cordis.yml` 组合；挂载时机：agent 创建时的 `setup(agentCtx)`，失败则整次创建回滚；隔离红线：preset 内的服务必须带 `isolate` realm，禁止泄漏到进程全局；切换会落日志：`agent-preset/selected` 事件。气泡（大雄）：「同一个产品里，每个会话可以是不同『工种』的 agent？」
- **技术点**：preset 机制见 `packages/preset/agent-presets/`（`mountPreset`、`discoverPresets`、`resolveSessionPreset`）；重建会话时必须经 `resolveSessionPreset()` 而非只读 header。

### 第 6 段 ｜ 剧情：胖虎的权限申请
- **画布**：1080 × 1680px。上下缘满幅出血；上接缝落在办公桌，下接缝落在驳回章的红光。
- **版式**：对角线分割——左下胖虎拍桌申请，右上老师盖章驳回，底部大雄缩脖子格。
- **画面**：
