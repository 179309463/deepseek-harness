## 【全局风格设定 · 每集通用，务必严格遵守】

### 成品形态与生成流程
- 最终成品是**一张手机长图漫画**：宽度恒为 **1080px**，垂直向下滚动阅读，**全彩**，高清。
- 不要尝试一次生成整张长图。必须按【逐段脚本】拆成多段分别生成：每段是一张 1080px 宽、高度 1440–2160px 的竖版图片（按内容多少定高，高清渲染）。
- 全部段落生成后，按段序**垂直无缝拼接**为一张完整长图。拼接处不得出现白缝、错位或重复内容。

### 顶部与底部安全区（仅首尾两段）
- 仅在整张长图的**最顶部**留出 ≥200px、**最底部**留出 ≥200px 的安全高度：两处为背景/场景的纯净延展（不是白色边、不放任何人物、文字、道具），用于躲避手机状态栏、刘海屏、标题栏与底部手势区的遮挡。
- 除首尾两段外，其余各段上下边缘**满幅出血**，段与段之间不留任何空隙。
- 每段的上下接缝必须落在斜切格线、场景色块或天空/夜色上，**禁止接缝切过人脸、对话气泡或文字**。

### 画风
藤子·F·不二雄经典哆啦A梦角色形象 + 现代科技杂志编辑插画（editorial illustration）质感。角色为简洁粗线条漫画风，背景与信息图采用扁平化、等距线框、细腻网点纹理。整体是「印刷精美的技术杂志」，不是儿童绘本。全彩画面，高清、锐利、矢量感，2K 分辨率质感，禁止黑白稿与低分辨率感。

### 统一色板
主色哆啦蓝 `#2B9FE3`、深蓝 `#1B5FAA`；底色米白纸感 `#FAF6EE`；强调橙 `#FF8C42`；正文墨黑 `#222222`。架构图使用蓝白线框 + 橙色高亮关键路径；代码一律深色终端卡片（`#1E1E2E` 底、浅色等宽字）。夜景与情绪场景可用深蓝渐变，但每段都必须保持彩色。

### 角色锚点（每集造型必须一致）
- 哆啦A梦：蓝色机器猫，白肚皮，红项圈黄铃铛，四次元口袋，表情睿智从容
- 大雄：黄 T 恤、蓝短裤、圆眼镜，初级程序员，工牌写着「野比科技」，常背双肩包
- 出木杉：白衬衫，端正沉稳，手持平板或指向架构图
- 小夫：绿色上衣、尖嘴，爱炫耀，常拿手机秀自己的项目
- 胖虎：橙色条纹衫，体格壮，撸袖子，「大力出奇迹」做派
- 静香：粉色裙子，产品经理气质，拿需求文档
- 老师：深色西装，严肃但公正，部门技术总监

### 动态分镜规则（长图的灵魂）
1. **禁止横平竖直的均分宫格**。每段 3–5 格，格子大小错落，主格占该段画面的 40–60%。
2. 格线必须动起来：斜切面板、锯齿/闪电形分割线、弧形格、梯形格交替使用；允许「破格」——角色、道具或光效探出格线 10–20%，制造冲击力。
3. 阅读动线永远自上而下：用斜切格线的指向、虚线动线、角色视线与色块流向，把视线从每段顶部引到底部，再自然滚入下一段。
4. 版式库（每段从中组合选择，禁止连续两段使用同一版式）：斜切双格、上大下小锯齿分割、出血大图 + 浮动旁白框、左窄右宽梯形双格、纵向时间轴三格、中心辐射、Z 字动线三格、满宽全景格。
5. **画面必须充实**：每一格都要有具体场景环境（办公室、会议室、深夜街道、全息空间……）、角色动作或信息图，禁止大面积空白背景，禁止「一格一个人头 + 一句话」的敷衍构图。
6. 角色在单格内不超过画面 1/2，以全身/半身的场景化姿态出现（坐着敲代码、站在白板前、围着工位）；禁止大头像特写撑满整格。
7. 每段保留一个「视觉钩子」：一道斜切色块、一个出血的道具、一条贯穿的虚线动线、一片发光特效。

### 文字规则（手机阅读的生命线）
1. 全部使用中文，技术术语保留英文原词（如 plugin、loop、session）。
2. 字号按 1080px 宽画面计，必须大且清晰：封面主标题 96–120px；剧情小节题字 64–80px；旁白框与正文 40–48px；对话气泡 40–44px；最小的图注标注也不得小于 32px。
3. 对话气泡每句不超过 20 字，但每格可以放 2–4 个气泡形成对话回合，让故事娓娓道来。
4. 旁白一律用漫画式色块旁白框（米白底或深蓝底白字），贴在格子的上缘或下缘；禁止整段文字墙，禁止一段全是字没有画面。
5. **禁止出现任何页码与编号文字**：不写「第 X 页」「第 X 段」「第 X 格」，不写 01、02 之类的序号。剧情衔接用手写感题字（如「当天深夜」「周五下午」）或纯场景过场格。
6. 架构图采用等距线框风格，节点用圆角矩形/圆柱体，箭头标注数据流，关键路径橙色高亮；架构图必须**纵向分层**（自上而下），角色站在图旁的瞭望台或地面上仰望、指点。
7. 代码/伪代码用深色终端卡片，带行号和语法高亮，卡片一角可有迷你角色注释气泡；卡片上的代码必须与脚本所写**逐字一致**。

### 屏幕呈现规则
- **禁止出现浏览器或 Windows/macOS 窗口外框**：不要地址栏、标题栏、红绿灯按钮、窗口边框。
- 所有屏幕内容一律以悬浮全息面板、深色终端卡片、发光卷轴、数据流光带的形式融入漫画场景。

### 完整结构（必须有头有尾）

## 【本集设定】

- **本集目标**：完整走一遍 dsh 的主循环——从用户输入到模型请求到工具执行再到结果回填，讲清 turn / step / inbox 三级概念与 waterfall 事件链。
- **研发收获**：掌握 `ReactLoopAgent` 的事件序列；waterfall 必须 `next()` 的委托语义；`tools/pre-execute` 审批钩子；工具并发调度的 exclusive barrier / parallel pool。
- **领导收获**：理解「agent 做一件事」在系统里是一条可观测、可拦截、可审计的流水线——每一步都有事件落日志，危险操作有人工闸门。
- **故事梗概**：静香要给大雄的 agent 派一个真实任务：「把昨天的实验数据整理成报表，周五前发我」。大雄第一次带着「X 光眼镜」看自己的 agent 内部——哆啦A梦用道具「循环透视镜」把一次任务拆解成一座灯光璀璨的流水线工厂。中途胖虎乱入想插队下危险命令，被审批闸门当场拦下。
- **出场角色**：大雄、哆啦A梦、静香、胖虎、出木杉
- **结尾钩子**：大雄问「不同任务要用不同装备组合，难道每次都重开一条流水线？」→ 引出下集 profile / preset / 权限。

### 第 1 段 ｜ 封面：一次任务的奇妙旅程
- **画布**：1080 × 2160px。本段是全图第 1 段：**顶部 ≥200px 为安全区**（深夜蓝天空的纯净延展，无人物、无文字、无道具）；下缘满幅出血，与第 2 段无缝衔接。

- **画面**：顶部 200px 是渐变的深夜蓝夜空（纯净无物）。其下进入场景：一条发光的流水线轨道呈 S 形自上而下贯穿画面并出血到左右边缘，轨道上跑着一节节发光的事件车厢，车厢上隐约可见 `turn/start`、`tool/call` 等字样；哆啦A梦举着「循环透视镜」道具站在左下角，大雄扒在其中一节车厢上探出头。
- **文字**：
  - 标题区（夜空与主视觉之间）：系列题字「哆啦A梦讲 deepseek-harness」（48px，手写感）；主标题「一次任务的奇妙旅程」（约 110px，深蓝粗体白描边）；副标题「agent loop——turn / step / inbox 与工具执行管线」（44px）；角标小字「第 5 集 · 循环篇」（36px）。

### 第 3 段 ｜ 概念：先分清三个时间单位
- **画布**：1080 × 1680px。上下缘满幅出血；上接缝落在同心圆光晕，下接缝落在笔记格。
- **版式**：中心辐射——同心圆三层结构主格 + 三张定义卡错落排列。
- **画面**：
  - 格 1（主格）：题字「先分清三个时间单位」。画面中央是发光的同心圆靶心：最外圈 **turn（回合）**、中间 **step（步）**、核心 **inbox（收件箱）**；哆啦A梦用指示棒从外圈点到核心，大雄在旁做笔记。
  - 格 2（定义卡组，米白底，三张错落）：**turn（回合）**——一次完整的工作单元：从认领输入开始，到无事可做为止，可取消；**step（步）**——一次模型请求 + 该次请求引发的全部工具调用；**inbox（收件箱）**——两条队列 `next-turn` / `next-step`，随时接收新指令。
  - 格 3（底部结论条）：一个 turn 包含若干 step；你随时可以往 inbox 里塞新话——就像给奔跑的接力选手递纸条。
- **技术点**：inbox 的两条队列与 `followup` / `steer` / `inject` 三种写入方式见 `packages/core/agent/src/inbox.ts`。

### 第 4 段 ｜ 概念：三种「插话」方式
- **画布**：1080 × 1680px。上下缘满幅出血；上接缝落在跑道起点，下接缝落在对话格。
- **版式**：纵向三跑道——三条长度不一的跑道自上而下错落排列，哆啦A梦递纸条小场景收尾。
- **画面**：
  - 格 1（跑道一）：`followup`——纸条飞进标着 `next-turn` 的收件箱，接力选手跑完这一圈才拆开。标注：本轮做完，下一轮处理。
  - 格 2（跑道二）：`steer`——纸条塞进 `next-step`，选手在下一个岔口直接拐弯。标注：下一步就调整方向。
  - 格 3（跑道三 + 对话）：`inject`——纸条直接拍进选手手里，当场生效。标注：立即注入当前现场。气泡（大雄）：「『先别管报表了，服务器报警了』用哪个？」气泡（哆啦A梦）：「`steer`——下一步就拐弯，但不清空它已经在做的事。」
- **技术点**：三种输入方式是会话 steering（实时纠偏）的机制基础，全部经 inbox 进入主循环。

### 第 5 段 ｜ 架构：一个 turn 的完整时序
- **画布**：1080 × 2160px。上下缘满幅出血；上接缝落在闸门开启的光效，下接缝落在 turn/end 的落幕光带。
- **版式**：整幅纵向时序长卷（本集最重磅的一段）——一条自上而下的发光主轴贯穿整段，站点依次亮起，左侧标注事件、右侧标注动作，橙色高亮关键路径；大雄和哆啦A梦站在顶部的起点站台。
- **画面**：
  - 格 1（整幅信息图）：题字「戴上透视镜看到的全貌」。纵向主轴站点自上而下——`turn/start`（闸门开启）→ 认领 inbox 消息 + 组装 system prompt → `agent/pre-step`（瀑布闸门）→ `step/start` + 写入 `user/message` → `deriveMessages()` 投影历史 → `agent/request` → `llm/stream` → `assistant/chunk*` → `assistant/message` → `tool/call` → 工具管线 → `tool/result` → `step/end` →（若还有任务，画一条回环箭头返回 `agent/pre-step`）→ `agent/turn-stopping`（串行商议）→ `turn/end`。
  - 图注（橙色高亮）：每一个站点都会往日志里写事件——上一集的「时间之河」，就是这样一站一站流出来的。角标：权威定义见 `docs/architecture.md` Turn flow 与 `docs/agent-lifecycle.md`。
- **技术点**：时序严格遵循 `ReactLoopAgent` 实现：claim → pre-step → step → request/stream → tool 管线 → step/end → turn-stopping → turn/end。

### 第 6 段 ｜ 深度：waterfall —— 必须传递的接力棒
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在流水线光带，下接缝落在代码卡。
- **版式**：对角线分割——左上「放行」流水线，右下「拦截」流水线，中间斜切代码条。
- **画面**：
  - 格 1（左上三角）：一份发光文件沿流水线传递，每个工位盖章后喊出 `next()`，绿灯一路放行。
  - 格 2（右下三角）：一个工位按住文件不放，流水线停在这里，红灯高亮，后续工位全部暗下。
  - 格 3（中间斜切代码条）：
    ```ts
    ctx.on('agent/pre-step', async (req, next) => {
      if (shouldReject(req)) return reject()  // 短路：不再委托
      return next()  // 放行：交给下一个监听器
    })
    ```
    条上标注：`agent/pre-step`、`agent/request`、`tools/pre|execute|post-execute` 都是 waterfall；返回而不调 `next()` = 主动短路。气泡（出木杉）：「这是策略层的天堂——限流、守卫、改写请求，全挂在瀑布上，不动主循环一行代码。」
- **技术点**：waterfall 语义出自 Cordis；「Waterfall listeners MUST call next()」是仓库铁律，不调用即 short-circuit。

### 第 7 段 ｜ 剧情：胖虎的危险命令
- **画布**：1080 × 1920px。上下缘满幅出血；上接缝落在闸门蓝光，下接缝落在胖虎跳脚的地面。
