## 【本集设定】

- **本集目标**：讲透两个最能体现 dsh 架构自信的能力——agent 检查/挂载自己的插件（自修改运行时），以及上下文压缩（compaction）如何让长任务不「撑死」。
- **研发收获**：掌握 `cordis_inspect / cordis_define / cordis_run / cordis_stop / cordis_undefine` 五件套的语义与边界（进程内存、重启即失、vm 沙箱不是安全边界）；理解 compaction-basic 的 pre-step 压力检测、`surfaceOp: replace` 摘要替换与 context-overflow 溢出恢复。
- **领导收获**：自修改 = 系统可在运行中被 agent 自己扩展（效率上限），但它的边界被明确划出（安全下限）；压缩 = 长任务成本可控，token 预算不失速。
- **故事梗概**：承接上集深夜异象——大雄发现 agent 在「自检」。哆啦A梦淡定解释：这是它与生俱来的内省能力，就像机器人可以打开自己的检修盖。随后大雄让 agent 临时造一个「报表美化」小插件现场试验；下午长任务跑到一半上下文濒临爆表，哆啦A梦再演示「记忆压缩」——把吃撑的记忆面包压成一口大小的精华方块。
- **出场角色**：大雄、哆啦A梦、出木杉、胖虎（想把自修改当武器被拦）、老师（关心边界）
- **结尾钩子**：能力都齐了，老师问出终极问题——「这套东西，怎么接进公司现有的系统？值不值得全面铺开？」→ 引出大结局：协议、SDK 与落地路线图。

### 第 7 页 ｜ 深度页：压缩流水线 —— compaction-basic 的四步
- **版式**：跨页式横向流水线，四站错落高低排列，橙色高亮第二站「无模型剪枝」。
- **画面**：流水线四站：① `agent/pre-step` 压力计（tokenMeter 检测）；② 先无模型剪枝——超大 tool result 直接修剪；③ 仍超压 → 选最老的一段 surface，调 LLM 写摘要（复用 KV 前缀省钱）；④ 用 `surfaceOp: replace` 把原文区间替换成摘要。记忆面包在流水线尽头变成小方块。
- **文字**：
  - 标题：先免费剪，再花钱压，替换要成对
  - 站点标注：
    - 检测：每一步开始前量压力，超阈值才动手——不提前浪费

- **文字**：

  - 要点：

### 第 9 页 ｜ 对比页：三种「处理旧上下文」的姿势
- **版式**：左侧竖栏导航，右侧三条横向跑道（长度不一）。
- **画面**：跑道一「直接截断」：前面记忆被剪刀咔嚓（模型突然忘了任务目标）；跑道二「无限堆叠」：token 烟囱爆炸（成本失控）；跑道三「compaction」：压缩成方块整齐码放（橙色高亮推荐）。
- **文字**：
  - 标题：截断丢记忆，堆叠烧钱，压缩两害相权取其轻
  - 跑道标注：
    - 硬截断 → 丢掉的可能是任务目标本身（最危险的遗忘）
    - 不处理 → 成本与延迟随轮次线性上涨
    - 压缩 → 丢失细节但保留语义摘要；且因全程落日志，原始事件仍在磁盘上可追溯
  - 气泡（出木杉）：内存里压缩的是「上下文」，磁盘上完整日志从未丢失——这又是日志与投影分离的红利。
- **技术点**：压缩只改 surface（模型可见投影），append-only 日志完整保留——第 4 集架构的直接红利。

### 第 10 页 ｜ 启发页：内省系统的三个台阶
- **版式**：Z 字形动线，三级台阶向上。
- **画面**：出木杉和大雄沿台阶向上走：台阶一「可观测」（仪表盘图标）、台阶二「可干预」（闸门图标）、台阶三「可自改」（扳手图标）。

  - 台阶一：**可观测**——系统对自己有完整的自我描述（inspect 一切）
  - 台阶二：**可干预**——运行中的行为可以被策略层拦截与调整（waterfall 一切）

- **技术点**：自修改不是孤立特性，而是可逆副作用 + 事件溯源 + 审批体系堆叠出的高阶能力。
