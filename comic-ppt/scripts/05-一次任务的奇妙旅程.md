## 【本集设定】

- **本集目标**：完整走一遍 dsh 的主循环——从用户输入到模型请求到工具执行再到结果回填，讲清 turn / step / inbox 三级概念与 waterfall 事件链。
- **研发收获**：掌握 `ReactLoopAgent` 的事件序列；waterfall 必须 `next()` 的委托语义；`tools/pre-execute` 审批钩子；工具并发调度的 exclusive barrier / parallel pool。
- **领导收获**：理解「agent 做一件事」在系统里是一条可观测、可拦截、可审计的流水线——每一步都有事件落日志，危险操作有人工闸门。
- **故事梗概**：静香要给大雄的 agent 派一个真实任务：「把昨天的实验数据整理成报表，周五前发我」。大雄第一次带着「X 光眼镜」看自己的 agent 内部——哆啦A梦用道具「循环透视镜」把一次任务拆解成一座灯光璀璨的流水线工厂。中途胖虎乱入想插队下危险命令，被审批闸门当场拦下。
- **出场角色**：大雄、哆啦A梦、静香、胖虎、出木杉
- **结尾钩子**：大雄问「不同任务要用不同装备组合，难道每次都重开一条流水线？」→ 引出下集 profile / preset / 权限。

### 第 3 页 ｜ 概念页：turn、step 与 inbox
- **版式**：中心辐射图。中心是同心圆三层结构：最外圈 turn、中间 step、核心 inbox；引线连出三张定义卡。
- **画面**：同心圆如靶心发光；哆啦A梦用指示棒从外圈点到核心，大雄在旁做笔记。
- **文字**：
  - 标题：先分清三个时间单位
  - 卡片标注：
    - **turn（回合）**：一次完整的工作单元——从认领输入开始，到无事可做为止，可取消
    - **step（步）**：一次模型请求 + 该次请求引发的全部工具调用
    - **inbox（收件箱）**：两条队列 `next-turn` / `next-step`，随时接收新指令
  - 底部一行：一个 turn 包含若干 step；你随时可以往 inbox 里塞新话——就像给奔跑的接力选手递纸条。
- **技术点**：inbox 的两条队列与 `followup` / `steer` / `inject` 三种写入方式见 `packages/core/agent/src/inbox.ts`。

### 第 4 页 ｜ 概念页：三种「插话」方式

### 第 5 页 ｜ 架构页：一个 turn 的完整时序

### 第 6 页 ｜ 深度页：waterfall —— 必须传递的接力棒
- **版式**：对角线分割。左上是「放行」：文件沿流水线传递，每个工位盖章后喊出 `next()`；右下是「拦截」：一个工位按住文件不放，流水线停在这里，红色高亮。
- **画面**：两侧流水线对称但结局相反；中间斜切条上是代码卡片。
- **文字**：
  - 标题：瀑布事件——不喊 next()，流程就停在你手里
  - 斜切代码卡：
    ```ts
    ctx.on('agent/pre-step', async (req, next) => {
      if (shouldReject(req)) return reject()  // 短路：不再委托
      return next()  // 放行：交给下一个监听器
    })
    ```
  - 要点：`agent/pre-step`、`agent/request`、`tools/pre|execute|post-execute` 都是 waterfall；返回而不调 `next()` = 主动短路
  - 气泡（出木杉）：这是策略层的天堂——限流、守卫、改写请求，全部挂在瀑布上，不动主循环一行代码。
- **技术点**：waterfall 语义出自 Cordis；「Waterfall listeners MUST call next()」是仓库铁律，不调用即 short-circuit。

### 第 12 页 ｜ 启发页：循环是政策中立的
- **版式**：Z 字形动线三节点。
- **画面**：出木杉在白板画「薄循环 + 厚插件」：循环本体很薄，四周挂满策略插件；大雄把「我们自己的限流策略」贴纸贴到插件区。
- **文字**：
  - 标题：为什么 dsh 的循环刻意保持「薄」
  - 节点一：**循环只做调度**——发请求、跑工具、写日志，不做任何策略判断
  - 节点二：**策略全在瀑布上**——审批、限流、压缩、守卫都是可插拔监听器
  - 节点三：**换循环不是禁忌**——`agent-loop` 本身就是插件；但 99% 的需求应该通过挂插件解决
  - 气泡（出木杉）：改 loop 必须同步更新架构文档——这条规矩就是为了防止策略偷偷长进核心里。
- **技术点**：仓库规则「Plugins, not loop changes」：新行为挂文档化的扩展点；改 `agent-loop` 必须更新 `docs/architecture.md`。
