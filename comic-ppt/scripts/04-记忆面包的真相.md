## 【本集设定】

- **本集目标**：讲透 dsh 最深刻的一条设计原则——「model-visible ⟺ logged」（凡模型可见，必可从日志重建），以及 SessionEvent 日志、surface 投影、持久化体系。
- **研发收获**：理解 `deriveMessages()` 为什么是模型历史的唯一来源；`SessionEventMap` 的 declaration merging 扩展方式；surfaceOp（append/replace）语义；`SESSION_FORMAT_VERSION = 0` 的预发布立场。
- **领导收获**：agent 的「每一次思考与行动」都有完整审计轨迹——这不是日志功能，而是合规、回溯、计费与事故定责的基础设施。
- **故事梗概**：承接上集——迁移沙箱后，大雄发现 agent 重启后「失忆」了：明明执行过的命令，问它却一脸茫然。大雄想起哆啦A梦的记忆面包，偷偷把「记忆」喂给 agent 的内存变量，结果进程一重启又全没了。哆啦A梦这才揭示真相：在 dsh 里，记忆不在任何「脑子」（内存对象）里，而在一条只增不改的日志里——模型看到的每一段历史，都是日志现场投影出来的。
- **出场角色**：大雄、哆啦A梦、出木杉、静香（提问「那用户删掉的对话呢」）
- **结尾钩子**：大雄问「日志里这些事件，是按什么顺序、被谁写出来的？」→ 引出下集 agent loop 主循环。

### 第 4 页 ｜ 概念页：只增不改的事件日志
- **版式**：跨页式横向时间轴。一条发光的日志长河从左向右流动，河上漂着事件卡片；右上角一个「禁止修改」印章盖在已流过的事件上。
- **画面**：事件卡片依次为 `turn/start`、`user/message`、`assistant/message`、`tool/call`、`tool/result`、`step/end`……哆啦A梦和大雄站在河边，哆啦A梦往河里放了一张新卡片。
- **文字**：
  - 标题：SessionEvent Log——只增不改的时间之河
  - 卡片标注：
    - 每一轮对话、每一次工具调用、每一个决策，都是一条不可变事件
    - 事件只能追加（append-only），永不修改、永不删除
    - 重启 = 把日志重新读一遍，「它」就回来了
  - 气泡（大雄）：所以「记忆」不是状态，是历史？

- **技术点**：`core/session` 是 append-only 的 `SessionEvent` 日志 + 内存 store（`ctx.sessions`）；重启恢复 = 重放日志。

### 第 5 页 ｜ 深度页：事件地图 SessionEventMap

### 第 6 页 ｜ 深度页：surface —— 从日志投影出模型历史
- **版式**：中心辐射图变体：左侧是「完整日志」（密集事件流），中间一台发光的「投影机」（`deriveMessages()`），右侧是「模型看到的历史」（简洁的对话序列）。橙色高亮投影机。
- **画面**：投影机把密集事件流过滤成干净的三色消息序列（user 蓝 / assistant 白 / tool-result 橙）；大雄站在投影机出片口接着「胶片」。
- **文字**：
  - 标题：模型看到的历史，是日志的投影
  - 要点：
    - 能进入模型历史的只有三种 surface 事件：`user/message`、`assistant/message`、`tool/result`

    - `session.deriveMessages()` 是唯一投影入口——模型请求的消息列表永远从这里产出
  - 气泡（大雄）：所以不存在「偷偷塞给模型一句话」？

- **版式**：杂志式不对称网格。左侧 2/5 深色代码卡片；右侧 3/5 拼图信息图：核心事件地图是底板，审批、预设、工具派发等插件各拿一块拼图嵌上去。

  - 标题：插件也能往日志里写自己的事件

### 第 11 页 ｜ 启发页：事件溯源思维带回家
- **版式**：Z 字形阅读动线，三个编号节点沿 Z 字排布。
- **画面**：出木杉在白板前画「日志 → 投影 → 视图」的通用图式；静香和大雄在旁听，静香举着「我们的订单系统也能这样」的便签。
- **文字**：
  - 标题：这不只是 agent 的设计——是事件溯源（Event Sourcing）
  - 节点一：**真相只存一份**——日志是唯一事实源，一切状态都是投影
  - 节点二：**可见即可重建**——凡是影响决策的输入，必须先进日志
  - 节点三：**读模型随便加**——标题、统计、审计视图都是新投影，不动写路径
  - 气泡（静香）：我们的审批系统……好像也该这么改。
- **技术点**：Event Sourcing + CQRS 思想在 agent 领域的落地：写路径（append-only log）与读路径（projections）彻底分离。
